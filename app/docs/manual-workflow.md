# 人工操作流程（应用 ↔ 导入包 ↔ 脚本）

> 这份是**给人看的操作手册**：一轮维护里，**哪几步必须你动手**、先后顺序是什么、做完怎么确认、
> 出了岔子怎么办。命令全部可以直接抄。
>
> 不重复的四份文档：
> `docs/guide.html`（应用里每个按钮干什么）｜`docs/auto-import.md`（crate 格式契约，给爬虫作者）｜
> `docs/scraper-guide.md`（爬虫侧怎么跑）｜`docs/field-rules.md`（字段与口径）。

---

## 0. 一轮维护长什么样（谁自动、谁手动）

```
   抓数据 / 判 nature / 综合成包              ← 脚本自动（一条命令）
              ↓  acm-data/nodes/all_nodes.json
   拖进应用（节点自动导入）                    ← 你
              ↓
   在应用里补/改 nature（③ 性质待补）          ← 你（这是唯一"人的判断"入口）
              ↓  「📤 导出人工填写」（**直接写盘**）
   acm-data/nature-assignments.json           ← 脚本替你写
              ↓
   下次产包**自动**把你的结论写回包里            ← 脚本自动（产包末尾那一步）
```

| 事情 | 谁做 | 入口 / 命令 |
|---|---|---|
| 判 nature、合成总包、体检 | 🤖 自动 | `npm run crate:all`，或应用里点「🛠 重建总包并导入」 |
| **抓数据** | ⚠️ **不是全自动** | 显式叫"抓"的只有第 2 步（QOJ 提交，每次联网）；**第 5 步"产包"自己也会联网**（见下面那张"哪几步联网"的小表）。杭电/牛客那两棵树自 2026-10-18 起**链上会产**（第 3/4 步，本地出包） |
| 校验包（离线试跑） | 🤖 自动 | 上面那两条的最后一步 |
| **补 / 改 nature** | 🙋 **你** | 应用「判重整理 · ③ 性质待补」 |
| **导出人工填写** | 🙋 **你** | ③ 那一行的「📤 导出人工填写」（点一下 = 写进 `acm-data/nature-assignments.json`） |
| 把人的结论写回包 | 🤖 自动 | 产包末尾（不用你再敲一条命令） |
| **把包搬进应用** | 🙋 **你** | 应用「📥 节点自动导入」 |
| **改分类词表 / 性质四字段的定义** | 🙋 **你** | ⏸ **界面先隐藏了**（用户 2026-10-15："性质注册表(分类)基本是写死的 ⇒ 建议先隐藏"）：现在只能命令行 `python -B scripts/nature-registry-check.py` 体检 + 直接改 JSON；要放出来见 §2.2 |

> **两条铁律**（下面的章节都围着它们转）：
> ① 你手改过的值**永远不会被导入覆盖**（性质字段是 `fill-if-empty`）—— 放心改；
> ② 但**重出包是从零生成的** ⇒ 不导出 baseline，你的结论就不会进包里（而且**看不出来**）。

## 1. 日常一：在应用里补 / 改 nature

**在哪**：`判重整理` → `③ 性质待补`（它列的正是"还缺哪几维"的节点）。

**三种动线**（按工作量从大到小）：

| 动线 | 怎么用 | 什么时候用 |
|---|---|---|
| ✍️ 推荐 | 行尾出现 `✍️ A·年份 2024` 这类按钮，**点一下才写** | 有证据（开赛时间/标识/名字）的年份、赛季 |
| 填充条批量 | 勾选若干行 → 在填充条填「分类 / 年份 / 赛季 / 地区」→ 点「填入选中」 | 一批同类（例如一整支省赛） |
| 点小标签 | 直接点行里那四个小标签（`分类:…`/`年份:…`/`赛季:…`/`地区:…`）→ 弹编辑框 | 单个精修 |

**看懂徽标**（分类那一格后面的字母）：

| 徽标 | 含义 |
|---|---|
| **M 人工** | **你定的**（手改 / 点了推荐）。比任何规则都硬 |
| A 权威 | 别人给的分类表 / 官方数据（CF `filterTypes`、QOJ 自己的分类路径） |
| B 结构 | 我们自己维护的结构（清单系列、标识 slug、路径里的地名） |
| C 明确字面词 | 赛名里写着的（`Regional` / `Final` / `省` / `Invitational`） |
| D 推断 | 靠词表/城市推（城市→赛区） |
| E 无依据 | 什么都没命中（`无归类`、停在浅处） |
| （没有徽标） | 老数据：那一列还没写（重导一次包会自动补上） |

**两个筛选用法**：
- 「依据」选 **`≤ C`**（"只看 C 以下"）= 挑出**该复核**的那些（靠赛名/城市推的）；
- 「依据」选 **`M 人工`** = 只看**你自己填的**（改错了来这儿找）。

**分类那一格是四种颜色**：绿 = 到叶子（填好了）｜蓝 = **有值但没到叶子**（还得往下补一层，
`未归类` 也在这档）｜灰 = **确定不用**（`无归类` / `上游异常`：都算填过）｜无色 = 还没判。
想一次挑出所有"停在中途"的：分类筛选选 **`（分类不完全）`**。

**地区**（现场地）有五个"不是地名但合法"的值，**都算填过了**：

| 值 | 什么时候用 |
|---|---|
| `无` | 这场**没有场地**（网络赛 / 线上轮） |
| `待填写` | **暂时不想填**（脚本已经给 UC、EC-Final、CCPC Final、女生/高职专场写了这个） |
| `不需要` | 这一维对这类比赛**不值得记**（国外英文地名） |
| `不知道` | 你也不知道（例如"一场跑好几个省"的多省赛） |
| `上游异常` | **上游坏了**（抓不到那一页 / 403…）⇒ 这一格判不了。四个 nature 字段都能用它 |

> ⚠️ **改一个值 = 那个值的依据变成 `M`**（原先的规则徽标会被替换）。这就是"人的结论"，
> 也是回代要保住的东西。

## 2. 日常二：把人工填写带回脚本（**一步**：点一下就行）

1. 在 ③ 那一行点 **「📤 导出人工填写」** —— 它**直接把结论写进** `acm-data/nature-assignments.json`；
2. 完事。**不用**再手动跑回代 —— 下次产包会**自动**带上。想先看会改什么：

```
npm run crate:baseline:report     # 只报：会回代几处 / 已一致几处 / 哪个 identity 不在包里
```

> **导出即写入**：点一下，**本机主脚本直接把结论写进** `acm-data/nature-assignments.json`：
> - **不备份** —— 这份文件本身是**导出物**（人工值住在节点的值 + `分类依据: manual:set`，
>   随「完整数据导出」走、IndexedDB 里也有一份）⇒ 丢了再点一次导出就有了；
> - **缩水先拒绝**：比磁盘上那份**少了节点** ⇒ 服务器 **409 不写**，应用弹一句
>   "少了 N 个（是哪些）"，你点确定才覆盖 —— 少了通常意味着"应用里那批人工值被别的操作冲掉了"；
> - 主脚本没起 / 接口 < v6 ⇒ 自动**退回到下载一份**并提示（要重启主脚本）。
> - 它靠的是本机主脚本的 `POST /api/nature-assignments`（路径写死在服务器侧，页面传不了文件名）。

**这份文件里装什么**：只有**人定过**的（级别 `M`）分类 / 年份 / 赛季 / 地区，外加
**人绑过的合成归属**（`ownerBindings`：你在应用里改过的「所属合成节点」）——
别的值（脚本判出来的）一个都不带（脚本重跑就能复现，不必往回搬）。
它很稳：值过不了注册表词表时**不写**并报出来；identity 在包里找不到也**只是报数**。

> ⚠️ **每次在应用里改完 nature 都要重新点一次导出** —— 这份文件是"你的结论"进脚本的那条路。
> 人在应用里改的东西**不进撤回历史之外的地方**：导入不进撤回历史，所以覆盖一份包**不能撤回**，
> 要恢复只能重新导入一份好的包（或重新导出这份 baseline）。

### 2.2 改"分类词表"本身（性质注册表）

> ⏸ **2026-10-15：设置里那一栏**隐藏了**（用户看过之后："性质注册表(分类)基本是写死的 ⇒ 建议先隐藏"）。
> 开关在 `ui/settings/settingsPage.js` 的 `SHOW_NATURE_REGISTRY`（改成 `true` 就放出来）；
> **服务端、判据、只读体检、面板与自测一个都没删**。所以下面第 1、3、4 步现在得靠"手改 JSON + 命令行"。
> 分类真的基本是写死的 —— 这一栏留着是给"以后真要动词表"那天用的。

**改的是规则，不是某个节点的值** —— `acm-data/nature-registry.json`（分类树 + 性质四字段的定义）：

1. （放出来之后）应用 **「⚙️ 设置 → 🧬 性质注册表」**（要本机主脚本在跑；它是**磁盘文件**，不进历史、不能撤回）；
   现在：直接改 JSON，改完先用下面那条命令体检一遍；
2. 里面能改：**四个字段**（`label` / `kind` / `pattern`，正则**实时**报能不能编出来）与**分类树**
   （加子 / 改名 / 删除 / ↑↓ —— ⚠️ **同级顺序有意义**：分类是有序列表落成的 `a/b/c`）；
   每行右边写着"**用它的节点 N**"（按前缀数）。**根与特殊叶子（`无归类`/`未归类`/`上游异常`）
   不许删** —— 少一片就有值判不出来（`natureFields.js` 的常量按字面比）。
3. 点「💾 保存到 nature-registry.json」——形状不过会被服务器**当场拒绝**（判据只有一份：
   `scripts/nature_registry_lib.py`），并在那一行显示"哪里不对"；
4. **保存后还有两步才算生效**（卡片里也写着）：
   - **刷新页面**：应用侧那份词表是在**模块求值期**读的（`core/natureFields.js`），不刷新还是旧的；
   - **重建总包**：`scripts/crate.py` 在链上读它，词表变了要重出包才落到数据里。
5. 命令行等价物（只读体检 / 自己也改坏了想核对）：
   ```
   python -B scripts/nature-registry-check.py            # 体检仓库里那份
   python -B scripts/nature-registry-check.py <某份.json> # 体检指的那份
   ```
   这份文件**在 git 里** —— 改坏了 `git checkout -- acm-data/nature-registry.json`。

## 3. 日常三：重建总包（一条命令 —— 或者**在应用里点一个按钮**）

```
npm run crate:all            # 联网全量重建 → 自动回代 → 自动校验
npm run crate:all:offline    # 同上，但一次也不联网（读本地缓存/归档）
npm run crate:xcpc:all       # 只产包那一步（注册表 / 合成包没动时用）
npm run crate:nk / crate:hdu # ⚠️ 这两棵树不在链上产 —— 要它们新，先各跑一次（见下面那段）
```

**或者：在应用「📥 节点自动导入」页点「🛠 重建总包并导入」**——

- 这条链跑在**本机那个"主脚本"里面**（`启动AcmTree.bat` = `scripts/dev-server.py`）：纯前端页面
  自己没法执行本机脚本；而那个服务器现在同时是页面的服务器**与**处理链的拥有者
  （见 [docs/scraper-guide.md](scraper-guide.md)）；
- 页面上**边跑边看日志与每步进度**（注册表 / 分类规则 / 产包 / 离线试跑，大约 2~3 分钟），
  跑完**自动把产出的包导入**；
- ⚠️ 自动导入有一道闸：**计划里 0 错误才自动执行**，有错误就停在预览让你逐条看（包已经准备好了）；
- 页面**从别的静态服务器打开也能用**（按钮会自己去试 `127.0.0.1:8321`）；只有当本机压根没在跑
  这个服务器时才会说"找不到主脚本"——那就双击 `启动AcmTree.bat`。
- 按钮点了没反应时它会**自己说清是哪种**：页面是旧代码（按 `Ctrl+Shift+R`）/ 服务器是旧进程
  （它通常已经自重启，若还报就双击一次启动脚本）/ 压根没在跑。
- 再双击一次 `启动AcmTree.bat` 是**安全**的：已经在跑就只开浏览器，跑的是旧版本就自动换掉它。
- 想关掉这个本机接口：启动时加 `--no-build-api`（或设 `ACM_NO_BUILD_API=1`）。

`crate:all` 依次做 **14 步**（离线档 **13 步** —— 第 2 步那个抓取必然联网，整步不进表），**步骤表只有一份**
（`scripts/build_chain.py`）：命令行 `npm run crate:all` → `scripts/build-all.py`，
应用那个按钮 → `scripts/dev-server.py` 在**同进程内**跑同一份表：

| 步 | 做什么 |
|---|---|
| 1 | `xcpc_registry.py build` —— 重出清单/注册表缓存（含"哪些场次归哪个系列"） |
| 2 | `QOJ_submissions_scraper.py --fetch` —— **刷新 QOJ 提交**（活数据；范围 = `me.json` 花名册，`active:false` 的账号按 `lib/me.py` 的口径不抓）。⚠️ **没配 `qoj.cookie` ⇒ 友好跳过（exit 0）**；**过期/被拦 ⇒ 当场停**（别静默出缺新提交的包）。必须排在产包**之前**（产包那步的 QOJ 适配器读的就是它刚写下的那份 JSON） |
| 3 | `hdu_multi_fetch.py build` —— **杭电多校树**（本地原料 → `nodes/hdu-multi-university.json`，**不联网**）。这台机器上没有那批原料 ⇒ **跳过**（不失败） |
| 4 | `nk_multi_fetch.py build` —— **牛客多校树**（`05 xcpc/cache/nk` → `nodes/nk-multi-university.json`，**不联网**）。同样"没原料就跳过" |
| 5 | `xcpc_pipeline.py --force --all-nodes` —— 跑全部适配器 → 各平台的包 → `all_nodes.json`；**末尾自动回代**（把你导出的 `nature-assignments.json` 写进包）。⚠️ 它把第 3/4 步写下的那两棵树**当成品读进来**，所以那两步必须在它之前 |
| 6 | `synth-bind.mjs` —— **建合成节点**（容器 + 组头）并按 nature 推**合成归属**（`ownerSynth`）：只补"签名唯一对应一个已有组"的，其余留给人定。⚠️ **建组只有这一步**（老的清单 slug 方案 `nature_rules.py` 已停用，理由见那个文件头） |
| 7 | `problem-bind.mjs` —— **题目绑定（P 随 C）**：以比赛组为单位按题号把各来源的 P 绑成一组；异常（题号对不上 / 题名冲突 / 整组无题名）**只报不动** |
| 8 | `nature-baseline.py apply --no-report` —— **补一遍回代**：组头是第 6/7 步才建出来 / 改名的，人工填的值要在这之后再回代一次才落得上 |
| 9 | `nature-rehome.mjs` —— 把"渠道没给分类"的节点按 nature 搬到位 |
| 10 | `clist-difficulty.py sync` —— 给包里已有的 P 补 CLIST 数值难度（**离线档跳过**；没凭据/网不通会友好跳过，不算失败） |
| 11 | `crate-check.mjs` —— **离线试跑**（0 错才算过） |
| 12 | `field-coverage.py` —— 字段体检（写进 `acm-data/reports/`） |
| 13 | `material-needs.py` —— 原料需求（写进 `acm-data/reports/`） |
| 14 | `embed-reports.py` —— **报告随包**（把上两份塞进包顶层 `reports` 一节） |

> ⚠️ **顺序是有理由的，别自己调**：2 必须在 5 之前（产包那步读它刚抓的 JSON）；
> **3/4 必须在 5 之前**（产包那步把这两棵树当成品读进来）；6 必须在 9 之前（9 会按同层规则把整表重排）；
> 7 必须在 6 之后（它要读刚定下来的 C 分组）；**8 必须在 6/7 之后、9 之前**（组头是那两步才建/改名的，
> 而那一步要用 nature 落位）；9 必须在 11 之前（试跑要看着搬完的包判"能不能导入"）；
> 12/13/14 必须最后（报告读的就是刚写出来的那个包，而且要**塞回包顶层** —— 写包那一步在它们之前）。

### 3.0 这 14 步里，**哪几步会联网**

（用户 2026-10-17 追问："所以现在建包,各平台只有 qoj 会尝试联网抓数据???" —— 答案是**不只**；
我先前那句"12 步里抓数据的只有 1 步"**说错了**：第 5 步（产包）自己会联网。逐条依据都写在代码里。）

| 步 | 会联网吗 | 抓什么 / 依据 |
|---|---|---|
| 1 `registry` | ❌ 不会 | 只读注册表 + 索引缓存，渲染出清单（`xcpc_registry.py:cmd_build` 里没有网络调用） |
| 2 `qoj-submits` | ✅ **每次** | 按花名册逐个账号抓**新提交**（链 argv 就是 `--fetch`） |
| 3/4 杭电 / 牛客两棵树 | ❌ 不会 | 只读盘上已有的原料（`build` 那一支；抓原料是另一条显式命令 `crate:hdu:fetch`） |
| 5 `crate`（产包） | ✅ **每次** | 它跑的那批适配器里 —— **AtCoder**（场次/题目是活数据，`CACHE_NONE` ⇒ 每次抓；提交按水位线只抓新的）、**CF 正式比赛**（`contest.list` / `user.status` / `problemset.problems` 都是活数据 ⇒ 每次抓）；**CF gym 榜单**与 **xcpcio** 只补"本地缺的那几场"；rankland / srk / pta / qoj 读本地文件，不联网 |
| 6–9 建组 / 回代 / 落位 | ❌ 不会 | 纯本地改包 |
| 10 `clist` | ⚠️ **只在没缓存时** | 缓存存在就"只回写"（`clist-difficulty.py:325`）；要补新题给 `--refresh`，全量给 `--force` |
| 11–14 试跑 / 体检 / 需求 / 随包 | ❌ 不会 | 纯本地 |

> 想**一次也不联网**：用 `npm run crate:all:offline`（第 2 步直接不进表、第 5 步带 `--offline`、第 10 步跳过）。

**还有四张表，链既不产、也不检查**（它们决定"包里该有哪些场次 / 哪些 gym"＝**范围**）：
`gym_whitelist.json`（范围，刷新 `python fetch_my_gyms.py`）、`rankland_index.json`（同一场在各平台的 id，
`build_rankland_index.py`）、`xcpcio_tree.json`（目录树，`build_xcpcio_index.py`）、
`cf_gym_meta.json`（gym 身份/分类，`gen_gym_manifest.py`）。
链尾现在会把这四张表的**年龄 / 条数 / 刷新命令**打出来（`📋 链依赖的人工表` 那几行）——
⚠️ **它只报年龄，不判"过期"**：白名单该不该变只有去问 CF 才知道，硬编一个"超过 N 天算旧"就是拿猜当判据。

**牛客 / 杭电那两个包现在链上就会产**（第 3、4 步，本地出包、不联网），下面这几条是**想单独重跑**时用的：

```
npm run crate:nk           # 05 xcpc 的"往年牛客多校"（自动抓路）→ nk-multi-university.json
npm run crate:hdu          # 02 hdu（杭电）本地原料 → hdu-multi-university.json（不联网）
npm run crate:hdu:fetch    # 要真去 HDU 抓页面时（要 me.json 里按年的比赛口令）
npm run crate:nk:browser   # 01 nk 的浏览器手存路 → nk-browser.json（**不进 all_nodes.json**）
```

⚠️ **2026-10-18 之前它们不在链上**：链的第 5 步只是把 `nodes/hdu-multi-university.json` /
`nodes/nk-multi-university.json` **当成成品读进来**合并成总包，链里没有任何一步会重新跑
`crate:hdu` / `crate:nk` ⇒ 链"从头跑到尾都成功"只说明**合并成功**，不说明这两棵树是新的
（2026-10-17 实测：链跑完，包里那棵杭电树只有 10 场，而原料里已经有 50 场）。
现在这两步**在链上**（顺序在产包之前），所以"忘了手动跑"这一类不会再有；
产包那步仍保留一句按文件时间比出来的提示「杭电那棵树**比原料旧**」，它只在**单独跑产包**时才有意义
（整条链跑的时候第 3/4 步刚把它们刷新过，那句话不该出现）。

它们也在 `all_nodes` 里，所以**回代在产包那一步（第 5 步）末尾就覆盖了它们**（不用各跑一次）。

**跑完看三行**：

```
✅ 可写入 N 个节点                          ← 最后一行；上面还有"新增/更新/跳过/警告/**错误 0**"
                                              （N 随包变：当前这份包 ~2.7 万）
✅ 已回代 N 处人工填写                       ← 回代那一步（没有 baseline 文件时会说"跳过"；当前 30 处）
📊 试跑结果：…｜错误 0                        ← crate:check
```

**想故意要一份"纯脚本产物"**（不带人工填写）：给产包命令加 `--no-baseline`。

### 3.1 刚打的一场（新提交）怎么进树 —— 原料 → 清单 → 包，三步都是**显式命令**

**判据：树上有没有这一场的 R，只取决于"那份提交原料里有没有它"，与计划 / 需求 / VP 名单都无关。**
（实测：今天 VP 的郑州站 `qoj.ac/contest/1873` 树上一串 R 都没有 —— 不是应用没导入，而是
**那份提交原料从没抓过它**；`--fetch --all` 只覆盖"清单里挂过 qoj 提交"的场次，它不在里面。）

| 步 | 命令（`<场次号>` = QOJ 比赛号） | 产物 | 怎么确认 |
|---|---|---|---|
| ① 抓原料（**范围由你给**） | `python -B "acm-data/raw/Scaper/04 qoj/QOJ_submissions_scraper.py" --fetch --contest <场次号>` | `04 qoj/qoj_submissions.json`（**一份跨比赛的文件**） | 结尾那行「比赛号分布：1873→12 条」 |
| ② 认身份（**人批准** = 持久的那一步） | `python -B "acm-data/raw/Scaper/05 xcpc/xcpc_registry.py" scan` → 看候选 → `… answer qoj:<场次号> yes --slug <slug>` | **注册表** `xcpc_registry.json` 那条多一个 `{source: qoj, …, contest: "<场次号>"}` | `… status` / `… find --suggest`；`scan`/`answer` 都可先 `--dry-run` |
| ③ 出包 + 导入 | `npm run crate:all:offline`（或在应用里点 **🛠 重建总包并导入**） | `acm-data/nodes/*.json` | 包里出现 `qoj:c:<场次号>:sub:*`；那个合成组头的 `ownerSynth` 对得上 |

⚠️ **清单 `xcpc_contests.json` 是注册表的产物，不是手改的文件**：链第 1 步 `xcpc_registry.py build`
会**整份重出**它（只从注册表渲染）。所以②必须落在**注册表**上。
`link_qoj_activity.py` 是**旁路**（它自己就声明"手工工具，不在链子上"）：它直接写清单 ⇒ 只对
"这次立刻出包"有效（`npm run crate:xcpc` 不动清单），**下一次 `build` 就把它冲掉**（实测 39→35）。

**四条判据**（这三步就是照它们排的，别绕过）：

- **除了"QOJ 提交"那一步，抓取都不在自动链上**：`crate:all` 主要是"把盘上现有原料重新打包"
  （`--list` 里只有第 2 步 `qoj-submits` 是抓取；其余下载器一个都不在）。表里的 ❌ 那些渠道
  要自己跑（清单见 `docs/scraper-guide.md` 的「哪些要手动跑」一节）。
- **范围永远由命令自己的选择器给**（`--contest` / `--url` / `--submitter` / `--all` …）；
  凭据文件里的花名册只是"**没给任何选择器**时的默认"，**不许把显式的 `--contest` 顶掉**。
- **"这份原料属于哪一场"只有一处声明**：**注册表**里那条的 `submissions` 引用（清单是它的渲染物，
  `link_qoj_activity.py` 只是旁路）。**不许另造一份"应该有"的名单。**
- **体检 / 原料需求只报告、不动作**：它按**空字段**列缺口与"该跑什么"，补不补是你显式跑
  `python -B scripts/build-all.py --needs`（或照它给的那条命令）。**缺口 ≠ 上游没有**；
  从别处**推断**出来的"应该有的东西"不能当抓取授权。

## 4. 日常四：把包搬进应用

1. 打开应用的 **「📥 节点自动导入」** 页（**不是**顶栏那个「📥 导入」——那个是**整库替换**）；
2. 选/拖 `acm-data/nodes/all_nodes.json`；
3. 看预览：
   - `新增 / 更新 / 跳过` 三个数 + 「警告」「错误」；
   - **`🔀 重挂 N`**：这一批会把 N 个**已在树上**的节点**按包的 `父extKey` 换父**
     （应用里没有别的换父入口 ⇒ 位置的真源就是包；0 = 位置一个没动）。
     明细在下面「会换父 N 条」那一栏里（从哪个父挪到哪个父），记录表里那些行尾部带 `🔀`；
   - **`⚠️ 性质不一致 N 条`**：包里判出来的性质与树上不一样。默认**不覆盖**，
     想看是哪几条点「只看这几条」；想让**包里说了算**就勾「**以包里为准**」（见下面 ⚠️）；
4. 点「▶ 执行导入」（整批一次事务，要么全成要么全回滚）。

**性质**：
- **幂等**：同一份包导两次没事（第二次全是"跳过"，只登记来源）；
- **位置以包为准**：记录的 `父extKey` 说挂哪就挂哪（已存在的节点也会被换父 ——
  应用里**没有**别的换父入口，只有同级上移/下移）。**包里的落位改动（`nature-rehome.mjs` 那种）
  就是这样进应用的**；换父会先在预览里报出来（`🔀 重挂 N`）；
- **你手填的值不会被覆盖**（性质字段 `fill-if-empty`）—— 包里带来的是空位或更细的值；
- ⚠️ **勾「以包里为准」会顶掉你手填的值，而且导入不进撤回历史**（覆盖了只能重填，
  或从上一次导出的 baseline / 整库备份恢复）。**不确定就别勾**。

## 6. 出问题怎么办

| 症状 | 原因 | 处理 |
|---|---|---|
| 应用里看不到某条的分类徽标 | ① 老数据（那一列还没写）② 那一格没值 | 重导一次包；或看来源面板确认是"空"还是"老数据" |
| 徽标是 `M` 却不是"权威" | 你（或推荐按钮）改过它 | 正常 —— M 就是"人定的" |
| 手填的值没进包 | baseline 没导出 / 放错路径 / 文件名带 `(1)` | `npm run crate:baseline:report` 会说"没有 baseline"或"命中 0 个"；放对再重建 |
| 回代里提示"identity 不在本包" | 那场次没了 / key 改了 | **不是错误**，只是提醒；确认那场是不是被删/改名 |
| 回代里提示"值过不了注册表词表" | baseline 是对着**旧词表**写的 | 在应用里把那个值改成合法路径，再导出一次 |
| baseline 被工具直接拒 | 文件形状不对（手改过 JSON？） | **别手改 JSON**，重新从应用导出 |
| 分类停在半路（蓝色） | 没到 Trie 的叶子 | ③ 里分类筛「（分类不完全）」逐个补 |
| 忘了导出就重建了 | —— | 不要紧：**应用里的值还在**（包不会覆盖已有值），导出一次再重建即可 |
| 导入后页面行为像旧代码 | 浏览器缓存了旧 ES 模块 | 按钮会直接说"页面是旧代码" ⇒ `Ctrl+Shift+R`；确认启动的是 `启动AcmTree.bat`（`dev-server.py` 带 `no-store`） |
| 按钮说"这个页面背后有服务器，但它不是主脚本" | 8000 上蹲着 **`python -m http.server`**（绑 `0.0.0.0`，没有 `/api/*`；我们的主脚本绑 `127.0.0.1`）。它默认 `allow_reuse_address`，所以再起一个照样绑得上、旧的也不退 ⇒ **会叠成好几个抢答**，重启/刷新都可能落在最老的那个上 | 先看是谁：`netstat -ano \| findstr :8000`，再 `tasklist /FI "PID eq <pid>"`；确认是 `python.exe` 后用 `taskkill /F /PID <pid>` 清掉，然后双击 `启动AcmTree.bat`。⚠️ 别用 `python -m http.server` 开这个应用 |

## 附：术语一页纸

| 词 | 意思 |
|---|---|
| **nature / 性质** | 分类（`xcpc/icpc/ec/final/official` 这种路径）、年份（举办）、赛季、地区，四个字段 |
| **分类到叶子** | 只有落在注册表 Trie **叶子**上的路径才算"填好了"；停在中间算缺 |
| `无归类` | **判过了**、这一支里没有它可归的一项（与"空 = 还没判"是两件事） |
| **依据强度** | A…E + M：这个值**凭什么**（不是"正确率"）。M = 人工 |
| **`分类依据` 列** | 包里记"这条值是哪条规则判出来的"的元信息列（应用据此画徽标） |
| **回代 baseline** | `acm-data/nature-assignments.json`：人定过的值的增量；产包末尾自动写回包 |
| **crate / 导入包** | 爬虫整理好的 JSON（`acm-data/nodes/*.json`），拖进「节点自动导入」 |
| **合成节点** | 把"其实是同一个东西"的几份归成**一组**的真节点（成员靠 `ownerSynth` 指针挂进去）。目前只有两种：**XCPC 的比赛**（同一场出现在多棵来源树里）、**CF/AtCoder 的复用题**（同一时间的不同场次里同一道题）—— **cf/atc 的比赛不合成**。⚠️ CF 那批复用题合成节点挂在**辅助树 `aux → aux-cf-contest → <年份> → 场次镜像 C`** 下、名字带 **`[Merged] `** 前缀（与老家那道 P 同父同名，不加前缀分不出谁是谁）。⚠️ 复用题的**老家那道 P 自己也算成员**（组 = 组头 + **所有**原料，含老家）—— 老家的状态要靠这个指针才进得了组值、才不会在判重页显示成"未归属" |
| **`以包里为准`** | 导入预览里的开关：让包里的性质**覆盖**树上的（默认关，会顶掉手填值） |
