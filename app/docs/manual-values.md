# 手改值的归属：客观 / 账户私有（设计稿）

> 起因：用户 2026-10-13 —— **"尽量允许用户自定义"**，重点是**如何实现「手改 + 客观」**
> （手填一个值，希望**对所有账户都算**，而不是只在填它的那个账户下可见）。
> 本文只给**设计**（现状 → 缺口 → 方案 → 拍板 → 判据）。**第一段（纯 core）已实现**（`v9.1.10`，见「已拍板」小节）；**UI 那一段也已实现**（`v9.1.12`）—— 见文末「实现进度与残余」。

## 手改值的归属

### 现状（代码事实，带行号）

| 事 | 在哪 | 现在的行为 |
|---|---|---|
| 值的形状 | `core/fieldValue.js:126` `addSourceValue(node, field, v, src, {at, account})` | 一条来源值 = `{v, src, at, account}`；**`account = ''` 就是"客观值"** —— 表示法**已经支持**"手改+客观"，缺的只是"让用户选" |
| 谁决定归属 | `core/ops/node.js:183-185` `recordManualValue` | `account = NATURE_FIELD_KEYS.includes(field) ? '' : draft.currentAccountId` ⇒ **只有 nature 四格是客观的**，其余手改一律记当前账户 |
| 清空怎么清 | 同文件 `:165-173` | nature 四格 ⇒ `removeManualFieldValue`（不看账户，清那一条）；其余 ⇒ `removeManualValue(node, field, currentAccountId)`（各账户各撤各的） |
| 多条候选怎么挑 | `core/trust.js:214` 的规则顺序 | **手改 > 字段级偏好 > 类别序（榜单>脚本>派生）> 来源等级 > 更新时间 > 先到** |
| 范围怎么过滤 | `core/trust.js:176-177` | **带账户的值超出当前范围就排除；不带账户的"客观值"永远算** |
| 导出 | 导出侧**不看账户**（把 `manual` 当人的结论带走） | ⇒ 客观值与被"导出"的私有值都同样会被带走 |

**关键推论**：范围过滤只**排除**，不排序 ⇒ 当"客观手改"与"本账户手改"**同时存在**时，
两者都是合法候选（都在范围内），于是按规则顺序继续比：`manual` 同级 ⇒ 类别同级 ⇒ 来源等级同级
⇒ **比 `at`（更新时间）⇒ 最近写的那条赢**。
⇒ **"手改+客观"不需要新增优先级规则**，只需要"能选归属" + "清空清对那条"。

### 缺口（要解决的）

1. **写的时候不能选**：手改一律按"nature 四格 / 其余"这个**字段名单**决定归属，与用户当下想表达的意思无关。
2. **清空的分流是按字段名单**，不是按"那条值自己的归属" ⇒ 一旦允许两种归属，清空就会清错那条
   （现在之所以没事，是因为每个字段只可能是其中一种）。
3. **界面不知道"这条值算谁的"**：字段表 / 编辑框只显示值，看的人分不清"这是所有人共用的，还是只有我能看见的"。
4. **导出侧没有明确取哪条**（客观与本账户私有同时存在时）—— 现在靠"每个字段只可能一种"侥幸不冲突。

### 方案（最小改动，符合"允许用户自定义"）

**① 写入时把归属变成显式参数**（口径只有一处）
- `recordManualValue(draft, node, field, before, after, opts)` 增加 `opts.scope`：
  `'objective'` ⇒ `account = ''`；`'account'`（默认）⇒ `account = draft.currentAccountId`。
- **字段默认值**仍走现有名单：nature 四格默认 `objective`，其余默认 `account`（**向后兼容**，老行为不变）。

**② 清空按"**这次编辑的归属**"清**（不再按字段名单）—— ✅ 已实现（`v9.1.10`）
- 实际落点：`removeManualValue(node, field, scope === 'objective' ? '' : draft.currentAccountId)`
  （`core/ops/node.js`）—— 归属由 `manualScopeOf(draft, field, opts)` 一处给出。
- 为什么**不**按"投影选中的那条"清（本文档原稿的写法）：编辑时 `viewing === current`（只读态禁止手改），
  所以"我的那条"就是 `currentAccountId`，不必去猜投影范围；按投影清会多一条依赖。
- ⚠️ **已知残余**：若"客观那条"比"我的那条"更新（按规则"最近写的赢"⇒ 屏上显示的是客观那条），
  而这次编辑的归属是 `account` ⇒ 清空会清掉我那条、**屏上的值不动**（用户视角＝"清不掉"）。
  罕见但真实；要治就得让调用方把"屏上那条是谁"传下来（UI 那一步再定）。

**③ 界面上让它可见、可选**
- **每张编辑表单底部一个三选项下拉**（「只有我能看见（账户私有）」/「所有人共用（客观值）」/「按字段默认（推荐）」；`settings.manualScope` 没设过 ⇒ 默认停在第三态，选它 ⇒ `scope = undefined` = core 按字段回落）—— 管**这一次编辑**（`opts.scope` 每事务一个值 ⇒ 不是每字段一个）；默认显示取**表单首字段**的回落；改选即写回 `settings.manualScope`（下次默认＝上次选择）。⚠️ 已知"半诚实"一处：`settings.manualScope` 未设 + 改性质四格 + 不动开关时，屏上写"账户私有"而 core 按字段回落记成客观（刻意，见文末残余）。
- 客观值的轻标记 `🌐`（`title="所有人共用（客观值）"`）：**值级面板**的 `sharedTag` 两分支都有；**📋 完整字段表**里
  来源行**本来就有**（它复用 `sourcePanel.js:buildSourcePanelHtml`），`v9.1.13` 又在**值那一格**加了一处表级标记
  （扫表不必展开 `<details>`）——副作用是单来源那行会有两个 🌐；
- 已有的按账户手改，给一个 **"转成所有人共用"** 的动作（把那条 `account` 清空的显式操作）。

**④ 优先级不新增**：沿用"同是手改 ⇒ 最近写的那条赢"（`trust.js:214`）。

### 已拍板（用户 2026-10-13）

1. **默认归属 = 记住上次选择** ⇒ 落成 `settings.manualScope`（`'account'` | `'objective'`）：
   用户最近一次在编辑框里选的那个值就是下次的默认；**它同时充当"设置里的全局默认"**（一件事，不设两处）。
   ⚠️ 未设置时按现状回落：nature 四格 ⇒ `objective`，其余 ⇒ `account`（**老行为不变**）。
2. **开关位置 = 设置里一个全局默认 + 编辑框可覆盖**（编辑框那次选择会写回 `settings.manualScope`）。
3. **一键"转成所有人共用"**（用户 2026-10-13 **第二版**，与首版的差别已按此改）：
   · **只对某些字段开放** —— 名单 `ops/node.js:OBJECTIVE_PROMOTABLE_FIELDS` = **比赛时间 `contestTime` + 各难度**
     （`cfDifficulty` / `atcoderDifficulty` / `clistDifficulty`）；`ratio`（通过率）与 `xcpcDifficulty`（派生）**不在内**；
   · 取**第一个取到的账户条目**（**不是**"本账户那条"，也不按时间挑）；
   · **客观那条已经存在 ⇒ 不动它**；否则客观取**第一个账户条目的值**；
   · 之后**所有账户条目消失**（留着会按"最近写的那条赢"把结果顶回去）；
   · ⚠️ **这个动作是破坏性的**（用户："破坏是难免的"）—— 它按定义要删掉那些账户条目。
   **功能保留**（以后还会用）。

### 判据（实现后必须能红的那些）

- **换账户仍可见**：把某字段手改成客观 ⇒ 切到任意其它账户，值不变（合成夹具 + 真包探针各一条）。
- **两条并存时最近赢**：先写客观、再写本账户（或反过来）⇒ 投影取后写的那条；两条的 `at` 都在。
- **清空只清一条**：清空后，另一条归属的值**还在**（这正是现在按字段名单做不到的地方）。
- **导出稳定**：同时存在两条时，导出**带哪条**要写死并断言（别让"今天导出带这条、明天带那条"）。
- 守卫落点：`src/test/` 新增一条单测（合成夹具）+ 现有 `dedupDisplay.test.js`/`elementTake.test.js` 不许变红。

### 已定（**不当欠账重开**）

| 项 | 定论与理由 |
|---|---|
| 「转成所有人共用」**只在编辑表单的值级面板**，不在 📋 完整字段表 | **就这样**：📋 那条链是 `ui/nodeinfo/nodeFields.js`，它 import 的是**纯 Node 可用**的 `core/fieldValue.js`；而按钮要调 `core/ops/node.js`（会牵出 `immer`）。为了一颗按钮把那条链弄脏不值。要转就去编辑弹窗转。 |
| **停用账户名下的手改**在面板里不显示 ⇒ 那种情况 promote 按钮不出现（core 其实能转） | **不治**（`v9.1.20` 定）：`explainField` 的 `stored` **按设计**剔掉"停用 / 悬空账户"的值（`fieldValue.js:687`）；让一个你**看不见**的值参与**破坏性**动作，比"按钮不出现"更糟。真要用：先把那个账户启用。 |
| **单来源那行会同时出现两个 🌐**（📋 完整字段表里：值那一格一个、来源行一个） | **保留**：值格那个是 `v9.1.13` 有意加的（扫表不必展开 `<details>`）；来源行那个是 `sourcePanel.js` 原有的，而**编辑弹窗里只有它那一份**（弹窗没有"值那一格"）。要去掉前者以外的那份就要给 `sourcePanel` 传"宿主已画过"的开关 —— 观感取舍，**要改就一句话**（约 3 行）。 |
| **极端情况下可能误标客观** | **不额外处理**：标记取自 `explainField` 的 `info.stored` 里 `selected === true` 的那条；它有个兜底分支（`visible` 为空、走 `projected.all`）里条目**没有 `account` 键** ⇒ 读成 `''`。与 `sourcePanel.js` 的 `sharedTag` **同源同限**；要治就得让 core 把"这条的 account"显式带出来（另一件事，没触发过）。 |
| **导出稳定**（原残余 2） | ✅ 已写死断言（`v9.1.20`），见上面「实现进度与残余」的残余 2。 |

- ⚠️ **教训（我犯的）**：我在给用户的点检清单里写了"📋 完整字段表里手改那条带 🌐"，但**没有先去核那条渲染链**是否真的会画它
  —— 实际那条链**本来就画**（复用 `sourcePanel.js`），而用户看不到的原因是**页面跑的旧模块**（要 `Ctrl+Shift+R`）。
  ⇒ **写"应该看到 X"之前，先在代码里确认那条链会画 X**（否则清单会把"模块没刷新"误导成"功能没做"）。
- ⚠️ **教训（我犯的，`v9.1.20`）**：残余写进文档就当"处理过了"是错的 —— 标注「未做」的东西**要么现在做完、要么当场给出定论**；
  "先留着，等撞到再说"会让用户下次再来问一遍（他这次问的原话是"有残余为什么不做完？？"）。
