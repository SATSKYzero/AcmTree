一、快速上手：从零到一棵树

这个工具用一棵树记录你的训练：平台 → 系列 → 比赛 → 题目 → 提交记录。 最少只要三步就能开始用：

  1. 点右上方 ➕ 添加根节点，选类型、填名字，建立入口。
  2. 在节点上点 ➕ 逐层添加子节点（如：平台 → 系列 → 比赛）。
  3. 到比赛节点后，用 📥 批量导入题目 一次性把整场比赛的题录进去， 比一个个手加快得多。
🧭 界面分三层：最上面那条（Acm_Tree 标题 + 指南 / 宽度 / 导入 / 导出 / 清空 / 折叠全部 / 账户） 是全局栏 —— 切到「数据统计」「判重整理」「设置」「体检」它也一直在； 往下是一级页签（主视图 / 数据统计 / 检索 / 节点自动导入 …）； 再往下、只在「主视图」里的是副页栏（主页 / 你的题单 / ＋ 新建副页）。
💡 建议的层级用法：
平台（W）＝ Codeforces / 牛客 / 洛谷；
系列（S）＝ Div2 / 省赛 / 某个训练专题（可嵌套，用来分组）；
比赛（C）＝ 具体一场比赛（Round 900）；
题目（P）＝ 比赛里的一道题；提交记录（R）＝ 这道题的每次提交。
⚠️ 数据只存在这台电脑的浏览器里。换个浏览器、清了浏览器数据就没了。 请养成导出备份的习惯（见第十三节），或依赖「定时导出」。

三、合成节点与判重整理

同一场比赛，往往从几个渠道各来一份（榜单一份、索引仓库一份）。它们的题号、题名多半对得上， 于是树上出现多份「看着像同一场」的节点。合成节点就是给这种情况准备的一个「组头」—— 它不合并、不搬动任何数据，只是让几份原料承认自己属于同一组。

两类真节点：原料 与 合成节点

怎么认说明
原料节点有 extKey（外部身份键） 真正装着数据的那一份，可以填「所属合成节点」
合成节点节点有合成标识（界面显示 🧩） 没有 extKey；不能再填「所属合成节点」（名单不能嵌套）

合成标识是它唯一的身份：一次手填、或由应用自动生成 synth:1、synth:2… （保留前缀 synth:，你自己填的标识不许用它开头）。

成员关系是「指针」，不是父子

原料上的「所属合成节点」（字段键 ownerSynth）写着某个合成标识， 它就归入了那一组。就这么一条规则。

  • 不是父子、不嵌套、没有环：归入不会让成员换个位置，节点还在它原来的地方；
  • 树上该怎么展开还怎么展开 —— 归入不给成员任何「祖先」资格；
  • 删掉合成节点不会带走成员，只是把指向它的指针清空（同一个事务里做完）；
  • 同类型才合：C 跟 C、P 跟 P、R 跟 R；W/S/O 不参与合成（开关是禁用的）。
💡 页面怎么写，跟分组没关系：判定「谁和谁一组」只看指针一种凭据， 页面上的推荐只是提示。清空指针 = 解绑。

怎么建、怎么归入

  1. 手建：走新建子节点流程，选完类型后界面多问一句 标记为合成节点（勾上再填名称与合成标识；标识留空就自动生成）。 合成节点挂在哪，仍受第十六节的类型约束。
  2. 判重整理页（🧩 判重整理）：在推荐那一行直接点 归入（归到一个已有的合成节点）或 新建合成节点并归入（顺手建一个再挂上）。
  3. 编辑面板也能改：节点字段里有一栏「所属合成节点」。 但那里要你亲手写合成标识；写错（树上没有这个标识、写成节点 id）会被直接拒绝、弹错。 日常归入/解绑请在判重页做。
  4. 导入包也可以带合成节点与指针，但有两条硬规矩：
    • 包不得覆盖树上已经存在（非空）的「所属合成节点」——这类改动会被拒绝， 并在预览里单独列一行告诉你有几条没写；
    • 目标合成标识不存在（悬空指针）、或写的是节点 id ⇒ 写路径直接拒绝：预览里报出来， 树上一个字节都不落。想改请到判重整理页手动归入。
    预览里能看到四项：「新建/更新合成节点」「设置成员指针」「被拒绝的指针改动」「悬空/非法指针」。

P 层的题目绑定（P 随 C）—— 同一道题在多个来源各有一条时

C 层（上面那些）解决的是"同一场比赛在多个来源各有一条"； P 层解决的是"同一道题在多个来源各有一条"（典型：CF 同轮 Div1/Div2 的复用题、 QOJ 与 CF 各建了一条）。做法是以比赛组为单位、按题号把 P 绑成一组 （链子里的 problem-bind 那一步，键 synth:problem:<场次标识>-<题号>）， 生成的 P 合成节点挂在那一个 C 合成节点下。

  • 只看题号判：题目名字只当显示名，不当判据；
  • 整组没有题名也能绑：组名用兜底名「题号（题名缺失）」；
  • ⚠️ 三种异常只报不动，等人处理：题号对不上（按题名也配不上）、 题名冲突（同一来源多出一条）、整组无题名。 它们出现在判重页的 ⑤ 冲突 那一栏；
  • 人怎么处理（两条路，都在应用里）：① 把那条 P 的 「所属合成节点」改成规范题号那一组（会写进 ownerBindings、随「📤 导出人工填写」回代）；② 在 acm-data/synth-registry.json 的 problemIdMap 里写一行 "某来源在某场次里的题号换算"（⑤ 栏会给出建议行，认就抄）。

判重整理页（🧩）：怎么读、怎么用

页面分五栏（二级 tab，一次只显示一栏；栏名上带条数，哪一栏有活一眼可见）： ① 合成节点（N）、② 可能重复（建议）、 ③ 性质待补、④ 概览、⑤ 冲突。 选好的筛选范围 / 关键词在切栏时不会被清掉（切栏只是换一块看）。 ⑤ 是只读的：同一来源多出一条、题号错位这类异常，它只报不动， 改不改由你（按它给的行去改 problemIdMap 或改节点的「所属合成节点」）。

  • ① 那块是「核对模式」：只把已经绑好的组列出来供你抽查、改名、改标识、解绑、删组， 不产生任何建议。
  • ② 那块才是建议，每条都写明依据。默认只出「机器能判定」的等价信号：
    • 双方题号（problemId）都非空且相同；
    • 归一化标题完全相同。
  • 跨性质不建议：分类 / 年份 / 赛季 / 地区对不上的一对，直接不出建议 （判定口径 = 只比两边都非空的那几维；一方没标就不拿它否决）。
  • 相似度建议默认关着，要显式点 开启相似度建议（噪声大）； 开了之后页面会常驻一条黄字警示：那些只是名字像，不是同一个东西，仅供人工扫一眼。

筛选范围：把候选缩到「能手工处理」的规模

  • 范围三档：整棵树 / 某个子树（选一个节点） / 单场比赛（一个 C 容器） （选「单场比赛」时旁边多一个按名字/标识过滤的「场次筛选」输入框）。
  • 再叠性质四维（从当前数据里收集，不穷举词表）、类型、 关键词（题名/题号包含）、归入状态（默认「只看未归入」）。
  • 右上角永远写着 命中 N 条建议 · 当前范围（含范围里有多少个节点）， 条件一变就重算重画；旁边有 清空条件。
  • 为什么「缩到单场比赛后通常只剩个位数」：整棵树上出的建议里，绝大多数是 同一套标题模板的噪声（(I) vs (II) 这种），缩到一场比赛之后 每场通常只剩个位数条 —— 所以「先缩小范围，再动手」是这一页的正确用法； 性质归类的用处是给出可靠的分区，不是替你消掉噪声。 （这套结论的来源与实测数据见 field-rules.md 与 auto-import.md 的相似度那一节。）
  • 建议只是提示：不点「归入 / 新建合成节点并归入」，一个字节都不会写。

③ 性质待补那一栏自己有一条「分类」chip 行（全部（N） + 每个第一段一个 xcpc（410） 这样的 chip，外加一个 没标分类（N））： 真实数据里待补项上千条、横跨好几支，所以先按分类的第一段缩到一支， 列表里的组头（分类 · 年份）才真的成组。

入选门槛：比赛（C）必须有分类 —— 连分类都没标的比赛 也会列在这里，行尾写「缺：分类、年份、地区」，填充条上有 「分类」下拉（Trie 里所有合法路径）可以就地补 （题 P / 提交 R / 容器 W·S 不背比赛级的性质，它们没有分类不算缺）。

③ 里有两行容易看混，这里分清：「筛选」那一行有四个字段 （分类 / 年份 / 赛季 / 地区，与 nature 四字段一一对应），选了就真的缩列表； 取值从当前列表收集，每一项都带「（没标…）」与「（有标…）」—— 后者是前者的补集 （无 / 待同步 这些"不是年份但有值"的也算有标）， 两边合起来就是全部；右边写 筛后 N / M 条 （最左边那个「分类」与上面那排 chip 是同一份状态，chip 只是"按第一段"的快捷方式； 下拉还能选更深的路径，选 cf/contest/div2 就只看它）。 「✍️ 批量填入」那一行才是要写入的值（每个字段都能「不改动」， 不改动就什么都不写），勾好条目 → 填值 → 点一次「填入选中的 N 条」， 同一批在一个事务里写完。

核对与填表：链接、跳转、年份推荐

  • 每一条都能点开：①②③ 里每个节点的名字都是链接，点它 = 跳到树上那个节点 （切页 / 展开祖先 / 滚动 / 高亮，与「🔍 题目检索」同一条路）；名字后面还有 🔗 链接 (N)，展开就是这一行的源站链接（按类别分组，与节点信息面板里那块完全一样）。 外链一律不带 Referer（有些源站按 Referer 防盗链，从本地页面点过去会回 403）。
  • 每行左边就是四个 nature 小标签（分类:… / 年份:… / 赛季:… / 地区:…，没标的显示 —）——点一下就能改： 弹出与「编辑节点」里同一套控件（分类是 Trie 下拉，年份/赛季带候选提示），改完走同一个事务。
  • 年份/赛季会推荐，但只推荐：③ 每行行尾可能出现 ✍️ A·年份 2024 / ✍️ B·赛季 2023 —— 点它才写进去； 按钮上那个字母就是依据强度（鼠标停着会解释）。两个字段各推各的： 「年份（举办）」只认本节点的开赛时间（拿不到时退到同一届的另一个来源填过的值， 再退到赛季反推，why 里会写明"可能差一年"）；「赛季」取标识 → 名字 → 父容器。 鼠标停在按钮上会看到"依据是什么"，请顺手核一下。 没有依据的条目连按钮都不画 —— 不猜；无 / 待同步 / 不确定 这些值也永远不会被推荐。
  • 勾选若干条 → 填充条上的 ✍️ 按推荐填年份/赛季：每条填它自己那些推荐值， 一次事务写完；推不出来的那几条不动，提示里会如实说"还有 M 条没有依据"。
  • 地区暂时不推荐：现在库里还没有一个真实地名（脚本对线上赛填「无」， XCPC 与 cf gym 留空等人工 —— gym 里很多其实是线下站）， 没有可学的样本 ⇒ 这一维老老实实手填。
    ⚠️ 这一维基本由管线自动填（重导一次包就带上）： 统一成中文城市 / 省名（Nanjing → 南京、澳門 → 澳门）， 网络赛写 无（没有场地）， Universal Cup 各站、EC-Final / CCPC Final、女生·高职专场写 待填写 （这一维暂时由人填，但算填过了 —— 不会挂在 ③ 等人补，想填时按值筛出来填）， 本身是英文写法的国外地名/赛区名写 不需要， 读不出就留空（不猜）。 填的时候候选里有 无 / 待填写 / 不需要 / 不知道 四个值可以直接点（脚本判不了那格时会写第五个 上游异常，见下）。 ⚠️ 四个值的分工：无 = 没有场地；待填写 = 暂时由人填（但算填过）； 不需要 = 这一维对这类比赛不值得记；不知道 = 人工填的（管线不产出）。
  • 顺便看"已经填好"的那些：勾上 同时显示已填满的节点， 它们会接在所有待补项之后（名字是绿色、没有勾选框、不计入条数）， 上面那三个筛选对它们同样生效 —— 用来回答"我这一族填成什么样了"。
  • 分类那一格的级别徽标回不来了？你已经改过的会标成 M （人工：这个值是你定的，比任何规则都硬）；只有老数据（那时还没有 分类依据 这一列）才没有徽标 —— 鼠标停在没徽标的那一格上会写明这一点。 "这条值是谁填的"始终能在来源面板里看到（手填的出处是 manual）。 ⚠️ 点「✍️ 按推荐填」也算你接受了那个值 ⇒ 一样标 M。
  • 回代：把"我定的那些"带回给爬虫（本页 ③ 那一行的 📤 导出人工填写）：导出的只有人定过的 nature（含你更早手填、 那时还没有标记的那些），直接写进磁盘上的注册表文件；之后每次产包都会把它带进包里 —— 规则以后再怎么改也漂不掉你的结论，换台机器导这份包也一样。 （它会先比一比，比磁盘上那份少了节点就拒绝并问你；机制细节见 field-rules.md §10。）

同组的 P/C 在统计里的合并显示要另外开： 设置面板里把计数模式从「不去重（默认）」改成「去重（以组为单位）」， 同一个组在范围内只算一次（判重页底部也写了这一句）。

四、性质归类（分类 / 年份 / 赛季 / 地区）

四个可选字段，用来回答「这条记录是什么性质的题/比赛」。 它们不参与任何计算，只做两件事：判重页的分区与筛选。 没标就是没标，空着不代表填错。

分类（不定层路径 + Trie）

📌 这一节后面几条是"分类判定的实现口径"（各渠道怎么判、优先级怎么排、规则 id 是什么意思）。 只想用应用的话，看上面「什么是合法值 / 什么叫填好了 / 灰蓝无色」就够； 这些细节在界面上以 tooltip 出现，想深究再往下读。

不再有「大类 / 小类」两级，换成一个「分类」字段 —— 值是一条不定层的路径（写进节点是 / 连起来的字符串），例如 xcpc/icpc/ec/pre/official（网络赛）、xcpc/icpc/ec/regional/official、 xcpc/ccpc/final/official、cf/contest/div2、atcoder/arc、 nk/多校。

  • 合法性 = 注册表里的一棵小 Trie（acm-data/nature-registry.json 的 classTrie，与 年份/地区 正交）。
  • 任何前缀都合法 ⇒「停在哪一层」本身就是信息： cf = 知道是 CF、还没细分；cf/contest/div2 = 已经细到 Div 2。 所以判得细就写细，判不细就停在浅处，不用编一个假值。
  • 但"填好了没有"只认叶子：cf、xcpc/icpc 这类停在中间的 值照样算「缺分类」（继续挂在③ 性质待补里，行尾会写「缺：分类（分类还停在 …，没到叶子）」）； cf/contest/div2、xcpc/icpc/ec/regional/official、qoj/无归类 这些叶子才算填好。 填充条与编辑弹窗的「分类」下拉里，没到叶子的路径都标着「（还没到叶子）」。
  • 现在判到哪一层：XCPC 一侧 xcpc/icpc/<赛区 ec·eu·jp>/<阶段>/<正式 or 热身>、 xcpc/ccpc/<阶段>/<正式 or 热身>， 阶段 = pre（网络赛 / Online）→ final（总决赛）→ regional（区域赛，也认「区域」两个字）→ 无归类，顺序就是优先级； CCPC 那一侧还多两条（优先级最高）：female（女生）、vocational（高职）； 名字里含「中国大学生程序设计竞赛」且不含「总决赛」的，也算 regional； 省赛 / 邀请赛 进 xcpc/provincial&invitational/<正式 or 热身>。
    末层 = official（正式赛）/ warm-up（热身赛） （xcpc 的各分支还要细分 official / warm-up）：赛名里写着 warm up / warming up / 热身 的进 warm-up， 其余一律 official。只有 无归类 不带这一层 （它没有"正式 / 热身"之分）。
    QOJ 一侧把 xcpc 那一套镜像到自己下面： 看那场在 QOJ 上的所有分类路径（一场常挂好几个分类）， 有一条过 icpc/ccpc 就算，并按路径里的赛区缩写落到那一段 —— aa / ec / ap / aw / eu / la / na / ne（ICPC 官方 8 个赛区， 见 qoj.ac/category/17）：例如 qoj/xcpc/icpc/ec/regional/official、 qoj/xcpc/icpc/eu/regional/official。 路径里是缩写表外的赛区 ⇒ 停在 qoj/xcpc/icpc （合法值，会挂在③ 等人补 Trie）；所有路径都不过 icpc/ccpc ⇒ 仍是 qoj/无归类。
  • ⚠️ 如果看到新分类被标成「（还没到叶子）」/蓝色：那是浏览器缓存了旧的注册表 （应用拿旧 Trie 判"到没到叶子"），硬刷新一次（Ctrl+F5）就好 —— 注册表现在是 cache: no-store 每次现取（core/natureFields.js）， 以后换注册表不会再出现这种情况。
  • 「年份」填的是举办年份，「赛季」填的是赛季年份（两个字段）： EC-Final / CCPC Final 常在次年办（2023 赛季的 EC-Final 在 2024 年 1 月举行）， 两个概念必须分开存。除那两种"总决赛"，其余比赛可以认为两者相同， 所以脚本在拿不到开赛时间时会用赛季年顶 —— 只有那两种总决赛例外： 它们的举办时间落在「赛季年 9 月 ~ 次年 8 月」，不唯一，硬填就可能差一年， 所以脚本给它们写 待同步（= 判过了、值在别处还没同步过来）， 而不是空着 —— 空着会永远挂在③ 里等人填一个只能靠别的来源才知道的值。 真要取值时，判重页会用「同一届的另一个来源填过什么」给你推荐 （同一场在别的来源树上常有真实日期，比如 QOJ 那场的 XCPC 镜像），点一下就填上。
    ⚠️ QOJ 的年份另有两条口径：非总决赛的举办年 直接 = 赛季年（QOJ 记的那些日期常是镜像/重跑时间：2022 的场次会被记成 2026）； 总决赛拿不到日期时写 待同步。
    「赛季」除了 20xx 还会是 无： 只有没有赛季概念的那些才这么写 —— CF 的正式轮次（/contests 那张表里的）、 AtCoder 的 ABC/ARC/AGC。写 无 = 「不适用」（与地区的 无 同一个意思，不是"没填"）。 ⚠️ cf gym 不写 无（原因： "单说 cf 有仅 cf contest 的含义" —— gym 不是 cf contest）⇒ gym 的赛季 = 举办年份； 牛客 / 杭电的多校同理（有赛季概念 ⇒ 赛季 = 举办年份）。
    年份与赛季都可以写 无 / 待同步 / 不确定（无 = 这一维不适用；后两个是为了"以后有用"）：前者 = 值在别处还没同步过来，后者 = 看过了但拿不准。 它们算「填过了」（不会挂在③ 待补里），但推荐绝不会给它们 （推荐 = "我有证据说是 20xx"）。填空的框里有候选提示（原生 datalist，只提示、不禁手输）。 判重页行尾的推荐按钮也是各推各的：「✍️ 年份 20xx」只认开赛时间、 「✍️ 赛季 20xx」认标识/名字/容器，一键按钮把两个一起填。
  • ★ 依据强度（A…E）：这不是"正确率"，是"这个值凭什么"。 A 权威（官方分类表 / 官方开赛时间）＞ B 结构（清单与注册表 / 标识 slug / 同一届的另一个来源）＞ C 明确字面词（赛名里的区域赛、总决赛、省份…）＞ D 推断（城市→赛区、省份词→EC、用赛季反推）＞ E 无依据。 填充条上那个「依据≥」下拉就是按推荐填的门槛： 选了 A 就只有"官方开赛时间"这类会写进去，D（默认）等于收下今天全部的依据。 ⚠️ 级别只控制"批量按推荐填"，不影响每行那个单独的 ✍️（那是你点名要写的）， 也绝不按级别回删已有值（库里大量分类本来就是 C/D 级得来的）。
    分类那一格也会带级别（分类:xcpc / icpc · A，鼠标停着会写清"是哪条规则判的"， 比如 qoj:path-icpc = QOJ 自己的分类路径、gym:infer-region = 靠城市/大区词推赛区）—— 那是爬虫写进包里的（每条判据一个稳定 id，记的是最弱的那一环， 因为值的可信度由最弱证据决定）。③ 的「依据」筛选就是按它挑活儿： ≤ C（"只看 C 以下"）= 把靠赛名/城市推出来的那些挑出来复核。 ⚠️ 人填的 / 老数据没有级别（分类依据 那一列是空的）⇒ 不画徽标、也不进任何一档"≤ X"：那不是"依据弱"，是"没有依据这回事"； 你手改了分类，旧依据会被清掉（值换了、依据没跟上就是撒谎）。
  • 判重页每行那几个小标签按状态上色（四态）：绿 = 填好了 （分类到叶子；年份/地区有值就算）、蓝 = 有值但没到叶子 （还得往下补一层）、灰 = 确定不用（特殊的"已填"，见下条）、 无色 = 还没判。
  • 灰 ≠ 空：空（无色）= 还没标，会一直挂在 ③ 性质待补里； 灰的那几个值都是判定结果 —— 从待补里消失，而且判冲突时当作"没有主张"。 灰值有三个，别混：
    • 无归类（分类维）= 判过了、这一支里没有它可归的一项 （比如 CF 这场比赛既不在 rated 全分类里、也没有 team / april / kotlin 的标记）；
    • 未归类（分类维）= 脚本判不出、等人补 ⇒ 算没填好：照旧挂在 ③ 里、也会被「（分类不完全）」筛出来 （只在省赛那一支的类型失配时由脚本写，是唯一一处）；
    • 上游异常（四个维都能用）= 上游本身坏了 （抓不到那一页 / 403…）⇒ 这一格判不了，灰、算填过。
  • CF 那一支按 CF 自己的 filterTypes 字段严格分类（不看赛名、也不管是否真的 rated）： 正式轮次全在 cf/contest/ 下（cf/div1 等（除了 gyms） 改为 cf/contest/div1）—— rated 的全分类 = div1~div4 / div1+2 / edu； 不在其中 ⇒ 先套 others，再按 team > april > kotlin 取第一个命中，都没有就 cf/contest/others/无归类。CF gym 上那些镜像/练习场是另一支 cf/gyms（刻意不在 cf/contest 下 —— gym 不是 cf contest， 而且它根本不在 filterTypes 表里，"表里查不到"不等于"归不了"）。
    gym 自己再细分一层（按这个方案）：gym 的赛名基本就是原比赛的名字， 所以那棵子树整棵照抄 xcpc：cf/gyms/xcpc/icpc/ec/regional/official、 cf/gyms/xcpc/ccpc/final/official、 cf/gyms/xcpc/provincial&invitational/official， 外加 cf/gyms/ucup（只有 Universal Cup 身份的）与 cf/gyms/无归类。 ⚠️ 优先级 = 省赛/邀请赛 → CCPC → ICPC → UC → 无归类：又含 CCPC 又含省赛/邀请赛的， 一律按「只是与 CCPC 有关系的省赛/邀请赛」算。
    UC Stage 特殊处理：标题写着 Universal Cup 的场次，主节点就是 qoj/ucup（那场自己的名字就是 UC 的一站）；若它的分类路径再过 icpc/ccpc（或落省赛），那份 xcpc 读法会另出一个 qoj:c:<id>:xcpc 节点（挂在对应的 icpc/省赛容器下，只照抄题单、不抄提交）——同一个 natureClass 装不下两种身份，之后在判重页把它们绑到一起即可。纯 UC 的只出一个节点。 ⚠️ 但「省赛/邀请赛」那一档只对 EC（中国）生效 —— 省、市、邀请赛本来就是中国的概念， 套到别的大区上就是错的（比如波兰的 Polish Collegiate Programming Contest 是他们的全国赛， 不是我们的"省赛"）。判 EC = 赛名里写着 China/Chinese/中国/CCPC， 或读出赛区 ec，或出现中国省名/大区词（Zhejiang、东北…）； 判不出就当不是 EC，落回赛区那一支。这条在 xcpc / qoj / gym 三处共用。
  • 筛选按前缀：选 cf 命中 cf/contest/div2、 cf/contest/others/无归类 等全部后代；选到 cf/contest/div2 就只看它。
  • 加一层 = 改注册表文件那一行（classTrie 里加一段），不用动代码。

年份与地区

  • 年份只认 20xx 四位（2026 对；26、2026年、 1999 都不对）；此外还允许 无（这一维不适用，如 qoj/ucup）、 待同步 / 不确定、上游异常（上游坏了、这一格判不了 —— 见上文"四态"那条）。 它不会替你补全或猜测：写 26 就永远是 26， 代价是「先缩到同一年」这条最有效的筛选会筛不到一起。
  • 地区是自由文本（成都 / Asia East / 澳門 都行）。刻意不穷举一份地区表 —— 写法在源头就不统一，穷举必然过期。 约定：判得出"线上赛、没有场地"的才写 无（CF 的正式轮次 / AtCoder / 牛客 / 杭电，由脚本自动填）； 拿不准就留空 —— XCPC 那类有真实场地的、cf gym（很多是线下站） 与 QOJ（上面挂着大量线下场次）脚本都留空，它们会留在③ 性质待补里等人补。

哪些是脚本自动填的，哪些要人补

字段现状
分类脚本会填，而且是唯一被明确要求先填好的： 每个适配器都在自己那一侧写下路径（xcpc / cf/… / atcoder/abc / qoj/无归类 / hdu/多校 / nk/多校）； 判定得到多细就写多细，判不细就停在浅处（停在 xcpc 完全合法）； XCPC 这一侧是每一场 C 都写，包括三个收集源那几棵树。 ⚠️ 归属判得出但归不进某一项的，写 无归类（≠ 留空）
（更深的层）脚本已经判到叶子：XCPC 是 xcpc/<赛系>/<阶段>/<official·warm-up>（如 xcpc/icpc/ec/pre/official、xcpc/ccpc/final/warm-up）、 CF 是 cf/contest/div2 这类。判不细的停在浅处（合法值， 但会挂在③ 等人补——"没到叶子"）；想加一层就改注册表 classTrie，不用动代码
年份能取就取：XCPC 取开赛时间（拿不到时非总决赛用赛季年顶）； CF / AtCoder / 牛客 / 杭电取比赛时间；cf gym 的赛季取赛名里的年份、年份取 CF 的开赛时间（两个都没有才留空；总决赛没有开赛时间写 待同步）；qoj/ucup 的年份与赛季都写 无（UC 既没有赛季概念、QOJ 那边也基本没记时间，与其空着挂 ③ 不如标成"不适用"）； QOJ 其余非总决赛直接 = 赛季年（它记的日期常是镜像/重跑时间）、 总决赛拿不到日期写 待同步；取不到一律留空（不猜）
地区判得出"线上赛、没有场地"的写 无（CF 正式轮次 / AtCoder / 牛客 / 杭电）； XCPC / cf gym / QOJ 一律留空（前两者源头只有拼音目录名或本来就是线下站， QOJ 上挂着大量线下场次 —— 拿不准就不填，别把"不知道"说成"不适用"）

从包里进来的这四个字段一律是「只补空」：树上已经有值就不动 （哪怕这个值是别的包或你直接改数据文件写进去的），只有空着的才让包补上 —— 所以「填过一次之后，重导不会被冲掉」。

这四个字段在编辑面板里都能改（「✏️ 编辑」页有分类 / 年份 / 赛季 / 地区四个控件，分类是 Trie 下拉、 年份与赛季带候选提示），判重页每行左边那四个小标签点一下也打开同一套控件。 从包里进来的值一律是「只补空」：树上已经有值就不动，只有空着的才让包补上。

五、状态值说明

比赛节点 (C) – statusComplete2

值含义
0未动：该比赛下没有题目或尚未开始处理
1有接触：至少有一道题有提交（无论是否通过）
2全部处理：所有题目均已标记为“已处理”（status1=1）
3AK：所有题目均已通过（status2=3 或 4）
4忽略：手动忽略该比赛（不参与统计）

题目节点 (P) – status2

值含义
0未使用：尚未开始做题
1待写：计划做题但尚未提交
2已提交未通过：有提交但未AC
3赛后补题：比赛结束后通过
4赛时通过：比赛期间通过
5忽略：手动忽略该题目（不参与统计）

3 和 4 是怎么分开的？看那次 AC 提交的性质 （每一条提交记录 R 上都有一个「性质」：赛时 / VP / 补题）—— 有一条赛时的 AC ⇒ 4 赛时通过；全是 VP/补题的 AC ⇒ 3 赛后补题； 判不出性质就按 3 算。性质是导入时由爬虫判断写进去的（判不出就留空， 界面上可以自己改）。你要"手动把它钉成赛时通过/忽略"也行：这两个是你按下的覆盖， 会存进来源层、不参与重算。

题目节点 (P) – status1（已处理）

表示“这道题我已经处理完了”，与是否 AC 无关，由你手动设置（0=未处理，1=已处理）。 它决定了比赛能否算作「全部处理」，也是统计筛选的依据之一。

💡 大多数状态是自动算的。你只需录入提交记录， P 的 status2、acTime、lastSubmitTime 与 C/W/S 的 statusComplete1/2 会按规则自动推导。
两个手动例外：把 P 的 status2 设为 5 忽略、 或把容器 statusComplete2 设为 4 忽略 之后，自动计算不会再改动它们。

六、添加、编辑、删除

添加

  • ➕ 添加根节点：在顶部工具栏，用于建立入口（平台/系列）。
  • 节点上的 ➕：添加子节点，会列出允许的类型。
  • Ctrl + 点击 ➕：跳过类型选择，直接用第一种允许类型添加。
  • 添加题目时如果留空题号，会自动按顺序生成（A、B、C…）。

编辑

  • 树形模式：双击节点 → 打开编辑面板。
  • 文件夹模式：Ctrl + 单击节点 → 打开编辑面板。
  • 节点上的 ✏️ 按钮同样可以编辑。
  • 如果在副页上编辑，会弹出「选择编辑对象」让你挑：两个按钮是 「编辑所映射主树节点」（改主树上的真实节点）与 「编辑本身」 （改这个虚拟节点自己的附加字段）。

标签与备注

⚠️ 备注（remark）是私有笔记，用之前先看这四条：
  • 导入永不写它：这是写死的规矩（不管包里写了什么、也不管节点是新建还是已存在）。 所以爬虫/脚本产不出「注意」「这题有坑」这类内容 —— 要写得你自己动手。
  • 它会进撤销快照：备注是节点字段，节点表整张进快照， 所以不要把大量文本放进去（写得越长，每一步撤销占的内存越多）。
  • 编辑入口就一个：节点菜单的 📝 备注（弹出「编辑备注」，多行文本框）。 保存走统一入口，会记一条「这是你手改的」来源。
  • 不限制长度，只提示你；想放长内容（题解正文、整段代码）请用别的地方（外部文件）。

删除

  • 节点上的 ✖：删除该节点及其全部子孙。
  • A + Q：在选中节点上快速删除（跳过确认）。
  • Ctrl + 点击 ✖：走带倒计时的确认框。

九、副页与题单

顶栏下方可新建副页，每个副页是一份独立的主树节点映射视图。

  • 可把主树里的节点「复制到副页」作为题单。
  • 副页内可添加虚拟节点、调整顺序，不影响主树。
  • 副页节点删除不影响主树；主树节点删除时，副页对应节点同步清理。
  • 副页的汇总状态读的是主树节点的实时状态——主树里标了通过，副页会自动跟着变。

按条件挑题 → 生成题单页

题单不用一道一道手动加：在任意节点上点 「更多操作」→「📋 待办题单」， 它会按条件把这个子树里的题复制到某个副页（那就是题单）。可勾的条件：

  • 状态2（未使用 / 待写 / 已提交未通过 / 赛后补题 / 赛时通过 / 忽略）—— 默认只勾前三档，另有一个「只要没处理过的也算」。
  • XCPC 档位（签到 … 金牌 … C+）、数值难度区间（留空 = 不限）、 标签、平台 / 赛系。多条之间是「与」，同一条里是「或」。
  • 目标副页可以选已有的，也可以当场 「➕ 新建一个副页…」并起名。
  • ⚠️ 设了数值难度区间时，没填难度的题会被排除（并单独提示），不会被当成 0 分混进来。
  • 条件会记着上次用的那份（只在这次会话里）——「再补一批」时不用重填； 重复的题会自动跳过，所以反复补不会越补越重。

副页的日常操作（新增 / 改名 / 删除 / 编辑虚拟节点）

  • 新建副页：副页 Tab 栏上的 「+ 新建副页」 按钮。⚠️ 副页数量上限 50 （到顶时新建会被拒，删掉不用的再来）。
  • 改名 / 删除副页：两样都在副页 Tab 上，不用去设置页 —— 按住 Ctrl 点 Tab 上的 ✖ 删副页； 按住 Ctrl 点副页 Tab 改名，会弹出「📄 副页设置」让你改名称 （删副页会连带它的虚拟节点一起没，但不碰主树）。
  • 编辑虚拟节点：副页里的节点点开是它自己那一页， 字段与主树编辑同一套界面 —— 改的是虚拟节点自己的附加字段 （题单里想单独记的东西），不会写回主树那个真实节点。
  • 顺序 / 层级：虚拟节点之间可以上下移、也可以套一层文件夹； 它只是"看的组织方式"，主树结构一个字节都不动。
  • 副页节点详页头部那两颗入口，各管一件事（从 v9.0.17 起）： · 那串蓝色的节点 id 点一下 = 跳到这个副页里的对应位置 （进它所在的页内文件夹 / 翻到它那一页 / 滚过去并高亮）； · 「🔎 跳到它引用的主节点」按钮 = 跳回主树上那个真实节点。 ⚠️ 副页根节点（代表"这一页"本身）没有页内位置也不引用主节点，那两样都不出现。
  • 副页里的题目列表也带那三样（从 v9.0.19 起）：副页节点详页的 「📊 题目分布统计」点柱筛出来的那批题，和主页同一处一样带着 「🔎 跳到这一页的位置 / 📋 打开详页 / 面包屑」三样 —— 🔎 用的是页内位置（切到它所属的那个副页再定位）， 面包屑是页内祖先链（带「📄 页名」前缀），不是主树那条。

待办题单（把未通过的题一次挑出来）

在 平台 / 系列 / 比赛 节点的菜单里点 📋 待办题单， 它会挑出该节点下未通过或待处理的题目，让你选择复制到哪个副页。

⚠️ 它是一次性快照。复制完成后再改主树状态，那份题单不会自动更新， 需要重新执行一次。
另外必须先建好副页才能用。

十一、统计与图表

总览统计（顶部栏）

  • C: AK/已处理/有接触/加忽略/总比赛数
    • AK = statusComplete2=3 的比赛数
    • 已处理 = statusComplete2=2 或 3 的比赛数
    • 有接触 = statusComplete2=1,2,3 的比赛数
    • 加忽略 = statusComplete2=1,2,3,4 的比赛数
  • P: 赛时过题/已过题/已处理/加忽略/总题数
    • 赛时过题 = status2=4 的题目数
    • 已过题 = status2=3 或 4 的题目数
    • 已处理 = status1=1 的题目数
    • 加忽略 = status1=1 或 status2=5 的题目数

这一条右边那颗 📋 = 超级根自己的详页：树只画超级根的孩子、 文件夹模式停在根目录时这一格只画统计 —— 所以超级根没有自己的方框， 这颗 📋 是它唯一的入口（副页停在它的「🏠 根目录」时同样有一颗，那是那一页的详页， 不是主树的）。

这些数字"按什么数"（计数标准）

上面那张表只说"哪一档算哪一类"。"数什么"是另一条口径，由 设置 → 📊 统计 → 计数模式决定（默认不去重）：

  • 不去重（默认）：子树里每个原料节点各算一次； 而合成节点只在"它本次子树内没有任何成员"时才算一次 —— 只要有一个成员在里面就不数它，否则同一场会被数两遍。
  • 去重（以组为单位）：同一个「组」只算一次。 组 = 一个合成节点 + 它的全部成员；没有合成节点的节点自己就是一组。 ⚠️ 去重是 scope-local：只看"这一次的范围（这一屏 / 这棵子树）"，不是全局去重。
  • 两种模式都按类型分别数：P 侧只数 P、C 侧只数 C（合成节点若不是 P 类型，本来就不进 P 的分档）。

档位从哪读：一律按当前「查看账户」现算（投影值），不是读节点上那个缓存； 去重模式下取「组那份」 —— P 侧把组内各来源的状态合并（有一处"过"就是过）； C 侧取两边的较大值（① 合成 C 自己子树汇总出来的那份， ② 组内各 C 成员自己那份的聚合）。

⚠️ 「忽略」不是"从总数里减掉"： C 侧加忽略 = 总数 −「未动」（0 未动只进总数）； P 侧加忽略 = 已处理 ∪ 已忽略。所以别拿"加忽略"当"有效数"，它只是"没被漏掉"的那一档。

★ 「查看范围」还可以带子账户（设置 → 📊 统计）： 勾上之后，看某个账户时它的直接子账户的提交也算进"我这份" （状态、树上显示、统计都跟着变）；只看直接子账户，不递归到孙辈。默认不勾 = 只看本账户。

文件夹模式下进入任意节点，点视图页签 📊 题目分布统计。 它把该节点下所有题目按难度分档，用柱状图展示，柱子里按状态2 分层着色。

  • XCPC难度 / CF难度：两套难度体系可切换。CF 是数值区间，XCPC 是等级档位。
  • 显示「未填写」项：是否把没有难度的题目也算进去。
  • 筛选模式：决定哪些题目参与统计
    模式含义
    无限制当前节点下所有题目，不做筛选
    全局覆盖自身或祖先满足「主树选中」或「副页映射覆盖」
    仅主页覆盖自身或祖先满足「主树选中」

AC 追踪（📊 数据统计页签）

顶部 📊 数据统计 页签下有三个二级页签：

  • 训练强度追踪：按天/周的热力图，看做题的密度与连续性。
  • 最近AC题目列表：按时间倒序列出最近通过的题，支持时间范围筛选。
  • 👥 账户对比：一屏里看多个人各自的补题情况（见下）。

👥 账户对比（一队 3 人各自的补题情况）

同一个页签下选「👥 账户对比」：左边一行是要对比谁（勾选账户， 默认就是你 + 你名下的子账户，最多 6 列），下面是表格。

  • 第一眼：每一场比赛一行，格子里是那个人在这场比赛的完成状态 （未动 / 有接触 / 已处理 / AK / 忽略）—— 一眼看出"哪场谁还没补完"；
  • 点比赛那一行展开：变成题目逐行，格子里是那个人在这道题的 状态2（赛时通过 / 赛后补题 / 已提交未通过 / 待写 / 未使用 / 忽略）；
  • 列头写着每人"通过 x / 共 y"；
  • 筛选：默认「只看差异（有人过、有人没过）」—— 这正是对比最有用的视角； 也可以切「只看有人没过的」「全部」，或只看某个人没过的题；右边还能搜题号/题名；
  • 点题目行直接打开那道题的编辑面板。
💡 这里只是"换个口径看"，不改任何数据、也不会偷偷切换你在查看谁。 每个人那一列，都是拿他自己的账户当"眼睛"算出来的 —— 所以"我过了、他没碰" 会老老实实显示成一边绿一边空，而不是两边都显示同一个值。

🏁 比赛补题概览（插件）

✨ 位置：文件夹模式下进入任意节点 → 视图页签 🏁 比赛补题概览（在「题目分布统计」右边）。

它把该节点下的每一场比赛画成一行，一行里横着排开这场比赛的所有题目：

  • 横坐标 = 难度，越靠右越难。背景的竖向色带就是难度档（XCPC 每档等宽；CF 完全线性）。
  • 每个点 = 一道题，按状态2 着色，点下方是题号。
  • 带橙色圈的题表示已被你「选中」（status1=1）。
  • 不支持难度的题会排在最左边的灰色带里（可用开关隐藏）。

看一眼就知道「哪场比赛补得最烂、欠在哪个难度段」，很适合赛后复盘。 控件与「题目分布统计」一致（筛选模式 / 显示未填写 / XCPC↔CF 切换）。

十三、保存、导出与导入

  • 自动保存：数据定期保存到浏览器 IndexedDB（默认间隔 10 分钟，可配置）
  • 定时导出：当数据修改后，若超过设定间隔未手动导出，将自动导出 JSON 文件（可配置导出类型）
  • 手动导出：顶部工具栏提供 4 种导出方式

导出类型

  • 📦 完整数据 – 含主树、副页、设置、元信息、来源层、账户（JSON）
  • 📦 完整数据 (.gz) – 完整数据的 gzip 压缩版
  • 📝 Markdown – 所有 P 节点的表格（路径 / 题号 / 名称 / 比例 / 难度 / 状态 / 标签 / 链接）
  • 📊 CSV – 同上，CSV 格式

导入

顶部工具栏「📥 导入」按钮可导入完整数据文件（.json 或 .json.gz）。

爬虫包（acm-data/nodes/*.json）走的是 节点自动导入那一页：预览里会逐条列出"新增 / 更新 / 跳过"。 包里的「性质」判定与树上已有的值不一样时会单独报出来 （汇总栏「⚠️ 性质不一致 N 条」+ 记录表最右那一列，鼠标停着能看到 "树上「A」→ 包里「B」（依据 规则id）"，点「只看这几条」就只留它们）。 默认不会覆盖已有的性质（fill-if-empty：你手填过的值不该被一次重导冲掉）； 想让包里的判定说了算，就勾上旁边的「以包里为准」—— 计划会当场重算，那几处的 tooltip 变成「★ 本次会覆盖」，点执行才真的写。 ⚠️ 勾了会顶掉你手填的值（且不能撤回），所以它默认关、 换一份新包时也会自动回到"关"。⚠️ 只覆盖非空的（不会把值抹空）。

⚠️ 警告：导入会完全替换当前数据（含主树、副页、设置、账户），并重置撤回历史。导入前请先导出当前数据备份。
💡 较早导出的存档里没有账户数据。导入这种文件时， 你现在的账户注册表会被保留（不会被清空）——否则"谁是谁"这套映射会凭空消失。

注意区分：这里的「导入」是整库恢复； 往某场比赛里录题目请用节点菜单的「📥 批量导入题目」（见第十节）。

「📥 节点自动导入」那一页上还有这几样

  • 「🛠 重建总包并导入」 —— 一键让本机主脚本把整条链 （清单 → 分类规则 → 产包 → 合成绑定 → 题目绑定 → 落位 → 难度 → 试跑 → 体检 → 需求 → 报告随包） 跑一遍，跑完自动把新包导入。这个按钮无条件出现：启动脚本带本机接口 （默认开）时正常跑；用 --no-build-api 关掉接口后按钮照样在，点了只会在日志里报 「用不上本机"主脚本"」，并提示你双击一次 启动AcmTree.bat。跑的过程中别关标签页。
    那个日志框：标题那行就写着进度（每步 ✅/⏳、当前档位、耗时）； 右边的「▾」可以把它收起来（只留标题，随时再展开）； 跑完不会自己消失（以前点一下别处就没了）—— 想清掉就按「✕」。
    ⚠️ 这份文件夹里没有抓取缓存时（刚拿到的副本、新机器）：第一步「注册表」需要的 rankland 索引本来不存在，它会先自动跑一遍 build_rankland_index.py 把它建出来再继续 —— 要联网，可能要十几分钟，日志里会有那句 「⚠️ 缺 … 现场建一份」。等它建完就正常往下走；中途断了就重来（已经建好的不会再建）。
  • 「离线重建（不联网，用现有原料）」 —— 是工具栏上「档位」下拉里的 一项（6 个档位都在这个下拉里）。选它只跑 不需要网络的步骤（跳过联网抓取与 CLIST 难度），用本地已有原料重建。适合"我只改了分类规则 / 绑定， 想重出一份包"。
  • 「全删重爬（先去无用原料，再整份重抓）」 —— 下拉里最重的那一档， 也是唯一会删东西的一档：先把"已经确定用不上"的原料去掉 （比如 gym 白名单改小之后，白名单外那些 gym 的榜单/提交缓存），再把各来源整份重抓。 判断"用不上"的规则只有一处（acm-data/raw/Scaper/lib/material.py）， 说不清的一律留着。其余五个档位只增不删： 缺的才抓，抓不到就保留旧文件。
  • 「🔑 补身份键」 —— 给树上已有、但没有 extKey 的节点补写身份键 （老节点 / 手建节点没有身份键 ⇒ 下次导入会当成新节点又建一条）。它有独立一页： 按父容器列出缺键的节点，预览要补什么，提交时先预检冲突（与别的节点撞 key 会拒）。
  • 自动监测新包 —— 点 「📂 选择爬虫输出目录」授权一个目录后， 新包一出现会自动提示（浏览器需要你授权那个目录）。
    导入记录（最近 50 次导入的来源 / 时间 / 新增·更新·跳过）只在数据里记着 （settings.autoImport.history），界面上没有任何入口能看到它。
  • 「🔎 / 📋」逐条记录表 —— 表里那份「这一包会动什么」的清单默认只画前 250 行 （真包一次导入能有两万多条），下面那行灰字写清「还有 N 行未显示」，旁边一颗 「显示全部 N 行」按钮点了才全量铺开（行数多时页面会卡，所以不默认铺）。 ⚠️ 那只影响画出来的行：计数与真正要写入的内容一个字不变。

「合并显示」：判重开了之后，树与统计按"组"算

判重整理把同一道题 / 同一场比赛的多个来源绑成一组之后，显示与计数 有两种口径。开关是 设置 → 📊 统计 → 计数模式，判重整理页 ④ 概览上那个 [不判重 / 判重] 按钮是同一个键（没有第二套口径）：

口径树上显示统计 / 图表导出
不去重（默认） 每个节点显示自己那份值每个节点各算一次原样（每个节点一条）
去重（以组为单位） 组里的 状态1 / 状态2 显示「组那份」 —— A 平台 AC 了，B 平台的副本也亮 一组只算一次（分布 / 总览 / 热力图 / AC 列表都按组） 不受影响（导出的永远是数据本身）

⚠️ 三点：① 有「组那份」的字段不止状态 —— 状态1 / 状态2、 AC时间 / 最新提交、各难度（CF / AtCoder / CLIST / XCPC 通过率与等级） 都有；比赛时间与「链接分类」按需合并。② 编辑表单与导出里看到的永远是你自己那份 （否则一保存就把组值写成了你的值）。③ 判重模式下还能逐字段挑读哪一份： 设置 → 显示 → 「判重模式下：各字段读哪一份」（自动 / 本份 / 合并那份）—— 选「本份 / 合并那份」只在判重模式下生效（不判重时一律读本份）。

十四、数据安全

  • 历史撤回：所有写操作均自动记录历史，可撤回最近 n 步（默认 25 步，可配置 1~100）
  • 存储提醒：估算体积 ≥40MB 时信息栏出现黄色「存储接近上限」，≥45MB 时变成红色「存储已满」并弹一次提示
  • 展开节点保护：展开节点数超阈值（L1=2500）时悬浮提醒，超 L2=5000 时阻止展开
⚠️ 存储提醒只是提醒，不会阻止保存。 它的数值是估算的：按每个节点各自的 JSON 长度缓存起来累加 （不是每次整份序列化），而且改完数据后大约 5 秒才刷新那行数字 —— 所以刚改完看到的是上一次的值，别拿它当"我刚写了多少"。 它也不等于浏览器存储的真实占用。 看到红色提示请主动导出备份并清理——它不会替你停下。
💡 提示：所有危险操作（删除、清空、撤回、清空历史）均带有 3 秒倒计时确认，请谨慎操作。
💡 信息栏还会显示两个状态： ✅ DB已保存 表示已写进浏览器存储； ✅ JSON已导出 表示当前数据版本已经导出成文件了。 如果显示「JSON未导出」而你又改过数据，说明该备份了。

十七、常见问题

改了东西，界面没反应 / 重启后没了

极少见。先看信息栏是否显示「DB未保存」；如果一直这样，可能是浏览器存储被占满（见第十四节的存储警戒）。

看不到「子节点」「题目分布统计」「比赛补题概览」页签

这些页签只在文件夹模式显示。切到文件夹模式即可（见第七节）。

改了代码/更新了版本，但页面像是旧的

按 Ctrl + Shift + R 强制刷新。 浏览器会缓存 JS 模块，偶尔会新旧混用。启动脚本用的开发服务器已经禁用了缓存，若仍反复出现， 确认启动的是 scripts/dev-server.py 而不是旧的 python -m http.server。

难度统计里为什么有「未填写」一堆

题目没录 CF 难度或通过率时就会归到这里。可以用「显示未填写项」开关把它隐藏， 或先用「📝 题目信息批量导入」把难度补齐。

XCPC 难度是怎么来的

由题目填的通过率自动推导成等级（签到 / 铁牌 / 铜牌 / 银牌 / 金牌 / R / C 等档位， 每档还有 +/-）。所以想让它准确，关键是填对通过率，不必手选等级。

副页会跟着主树变吗

汇总状态会，节点本身不会。副页节点通过映射指向主树节点，所以主树里标了通过， 副页的统计会自动更新；但副页的节点列表是你当初复制/映射的结果，主树新增的节点不会自动出现在副页里。

「待办题单」为什么不更新

它是一次性快照（见第九节）。改了主树状态后需要重新执行一次。

十八、账户（这份数据是谁的）

顶栏那个 👤 本机 就是账户入口。账户不是树的节点， 它只是一张名单，回答一个问题：某个值是"谁的"。

界面上只有两个概念：

  • ✅ 以它登录：你手改的值以谁的名义记下来（当前那个按钮上就是 ✅）；
  • 👁 查看它：点了就用谁的眼睛看数据（正在查看的那张卡上标着 👁 查看中）。
⚠️ 两者不同时，手改会被拒绝（这样才不会把自己的修改混进别人的数据）。 此时顶栏标记会变红并写出"在查看谁"。导入不受影响 —— 导入是客观数据入库，与"现在登录的是谁"无关。

每个账户下面可以填一串映射，格式是「源 : 字段 ＝ 值」，例如 qoj : 提交者 ＝ someone。导入时应用会拿记录里的线索去查这张表： 认得出就记在该账户名下，认不出就报出来（提示你去补一条映射）， 绝不自动新建账户。

归认的结果在三个地方看得到：

  • 导入预览（还没点执行时）：「归认：N 条 → 主号」；
  • 导入完成提示：「…… ｜ 归认：认出 N 条」；
  • 值级来源面板（双击节点 → 编辑弹窗里每个字段下面）： ← 来源 · 👤主号 #后4位；没有账户的值会明确写成 · 客观（意思是"这条值不属于任何账户"，比如榜单算出来的通过率）。

⚠️ 一条提交只归一个账户，而且父子账户不会自动合并： "谁认领了那条线索，这条提交就归谁"。所以两个账户的热力图里出现完全不同的题是正常的 （例：个人号是 cf/atcoder/qoj 的账号、队赛是 hdu / 牛客 / PTA 的队号）， 两边既不是子集也不是超集。要让"看我的时候也算上队的"，就 把队挂成我的子账户，再勾上 设置 → 📊 统计 → 查看范围 → 把我的子账户也算进我这份（见上面「这些数字"按什么数"」那一节的最后一段）。 ⚠️ 别让两个账户都认领同一条线索：那会被判成"冲突"、谁都不给， 整条线索变成"客观值"（反而两边都算）。

每个账户都有一个 活跃 开关（默认开）。 只有活跃账户能当登录/查看账户、参与归认、出现在字段来源里； 停用只是"先收起来"——账户、它填的映射、它名下的值全都还在，随时可以启用回来。 以后想换号或做账户迁移时，先停用旧号是更安全的做法。 停用的账户收在单独一页（账户列表上方的 活跃 / 已停用 那一行），不跟活跃的混在一起。

新建一个账户：在 账户（N） 那一行右边的 ＋ 新建账户 上点一下 —— 弹窗里填名字、性质（默认「本人唯一账号」）、 可挂父账户、再一行行填映射（源:字段=值），保存后就是一个真账户（可撤回、随导出走）。 ⚠️ 这块界面有两个入口、是同一份：点顶栏的 👤 本机 直接弹窗，或者 设置 → 🔑 账户/名册 → 账户 那一栏（和 me.json 名册同屏）。两处改的是同一份数据。

⚠️ 它和下面 me.json 那份名册是两套存储：账户建在应用数据里， me.json 的 accounts[] 是"从账户算出来的派生"（要同步就按那颗 📤 写进 me.json（爬虫用）），改 me.json 不会反过来长出账户。 账户编辑窗里，映射行与已选的子账户都有 ↑ / ↓（顺序会存下来：映射的顺序就是 me.json 里 mappings 的顺序）； me.json 表单里每一格也有 ↑ / ↓， 换的就是文件里键的先后。

账户列表里的 ↑ / ↓ 可以 调整顺序（顺序记在数据里、随导出走；默认账户「本机」恒在第一位）。 「以它登录」「查看它」这一对按钮 每张卡上都在：当前那个是高亮（点它本来就没事可做），点另一个就切过去 —— 这样按钮不会因为"谁是当前"而忽隐忽现、行也不会跳。

设置页「🔑 账户/名册」那一栏分两页： 👤 账户（应用数据里的账户与映射，这里是真源）与 🔑 名册 / 凭据（me.json）（磁盘上那份抓取脚本的配置）。 名册那页顶上还有一块 🔐 登录态：把抓取要用的凭据 （QOJ 的 cookie、CF 的 key/secret、CLIST 的用户名/key）直接手输， 每行一个「🔎 探活」—— 用框里现在的值试一发（1 个请求，不用先保存）， 过期就把"去 me.json 改哪一份"那句话原样告诉你。

💡 第一次装、或刚拿到一份发布副本时，那份 me.json 还不存在 —— 这不算出错（发布包里本来就不带个人数据）：名册那页照旧是空白、可以填的， 账户页那颗 📤 写进 me.json（爬虫用） 也照旧点得动。 保存一次它就把 个人数据\me.json 建出来（连目录一起建）， 不用先去跑一趟抓取脚本。

一个值的归属是记录级的：同一条提交的结果、时间、链接都算在提交人头上； 题目的通过率、比赛时间这类客观数据则没有账户。你手改的值，会记在当前登录账户名下。

💡 树上显示的值是"现算"的：它按你现在在查看的账户算 （换一个人看，同一个节点会显示不同的值，但数据一个字节都不会变）。 不属于你在看的人的值不会参与统计；万一某个字段只有别人的值，树上会先显示它并加上悬停说明， 而不是让字段凭空消失。
信息栏最后一句写着当前"口径"。派生结论（过题状态 / 完成状态 / AC 时间 / 难度等级）也已经按在查看的账户算 —— 也就是"各自看到自己的补题情况"； 只有「我处理了吗」（状态1）还按登录账户算。
💡 "手改"怎么算：必须在编辑弹窗里真的输入过那个字段、 而且值确实变了——两条都成立才留一条手改记录。打开弹窗直接点确定不算手改； 点来源面板的「优先」也不算什么（那是程序在改值）。
派生字段（状态1/状态2/完成状态这类自动算出来的）不记手改——它们的值不是你填的。
💡 提示：多个账户填了同一行映射时，导入会把它当成冲突并不认领 （不猜是谁的）。这时请自己判断该归谁，删掉多余那条。
💡 补映射之后怎么修历史值：点账户界面里的 🔁 用当前映射重跑归认。它会先告诉你"会改几条"， 确认后只改"这是谁说的"，不动值本身，而且可以撤销。
重新导入同一个包也能达到同样效果（同一个线索只留一条，账户按最新一次算）， 不会在旁边多叠一条。

清除本机的个人数据（凭据 / 抓取产物）

把这份文件夹交给别人、或者自己不想留着那些"看得出是谁的"东西时，用仓库根目录下的 清除个人数据 文件夹里那个脚本： 清除个人数据\确认要清除个人数据\点错了请直接关窗口\清除个人数据.bat。 双击它本身什么都不会改（埋三层 + 纯 ASCII，就是防误点），它会问你三次： 先敲 go，再选级别 1 / 2 / 3，最后敲 yes —— 最后那个 yes 之前，一个字节都不写；任何一步答错或直接关窗口 = 什么都不做。

级别清什么
1 只凭据 me.json 与它的备份 → 换成空模板（cookie、key/secret 全没）
2 凭据 + 提交/榜单 再加本人与他人的提交导出、榜单统计（*_submits.json、*_rank_stats.json、 *_standings_*.json、*.srk.json、PTA_rankings.json、 team_submissions*.json 等）
3 全部 再加抓取缓存与页面归档（cache\、pages\、*.html、 *.log、*.png、*.bak）
⛔ 无论选哪一级，这些都不会被删： · 全部源码与文档（*.py / *.js / *.mjs / *.md / *.bat）； · 注册表与题库比赛清单（cache\ / pages\ 之外、 名字里含 problems / registry / contests / whitelist / tasks 的一律不动：field-registry.json、nature-registry.json、 synth-registry.json、nature-assignments.json、xcpc_registry.json、 xcpc_contests.json、gym_whitelist.json、各 *_problems.json / *_contests.json）； cache\ 里那些名字像"题单"的（*_problems.json、*.tasks.html） 照删 —— 它们是抓来的缓存，不是题库清单； · acm-data\nodes\ 里的产出包（含 all_nodes.json）、merged\ 的示例、 reports\ 的报告；acm-data\raw 之外的一切；仓库外的任何文件。 脚本运行时会先把这份清单打印出来给你看。

清完自己核一下：仓库根目录跑 npm test —— 应该全绿，只有几处依赖"个人提交导出 / 树包"的用例会自己 skip 并打印原因。

另一层"个人数据"：浏览器里的那份 —— 什么时候清、怎么清

这个应用有两层"个人数据"，清文件只能清掉第一层：

哪一层里面是什么怎么清
磁盘上的 me.json（凭据）、提交/榜单导出、抓取缓存与页面归档、_chrome-profile\（登录 cookie） 上面那个 清除个人数据 脚本（1 / 2 / 3 级）
浏览器里的 树上全部节点、提交、副页、训练计划 —— 真源就在浏览器的 IndexedDB 里（见第十九节） 只有在那个页面的控制台里跑 clearAll()（或者设置页 Ctrl+点「🗑 清空」）
⚠️ 两件最容易误解的事（都实测过）：
  • "硬刷新"（Ctrl+Shift+R） 不会清浏览器数据。它只是"绕过缓存重新取 JS/HTML" —— IndexedDB 一个字都不动。 所以刷新完页面还是满的，不是"没刷新成功"，是数据本来就没清。 反过来，改完 me.json 之后要刷新一次才能让设置页读到新值 —— 那一步是刷新，不是清数据，两件事别混。
  • 同一个地址 = 同一份浏览器数据。浏览器按"源"（协议 + 主机 + 端口）隔离，不看磁盘上那份文件夹。 只要都在 http://127.0.0.1:8321 上打开，换一份工作区副本（比如 release 包）拿到的还是同一份 IndexedDB；而且如果 8321 上已经蹲着原来那份的服务器，启动脚本会礼让 （只开浏览器、不换服务）⇒ 你看到的可能仍是原来那份，连 me.json 都是原来那份。 判据：副本里没有 个人数据\me.json ⇒ 真连到副本时「🔐 登录态」应该是空的 （表单空白可填，不是报错 —— 见上面那条）； 如果它还是满的，说明连的是别的服务器（看 http://127.0.0.1:8321/api/ping 里的 root 指向哪个文件夹，以及设置页底部的版本号）。

什么时候需要清（清磁盘和清浏览器是两件事，按需做）：

  • 要把文件夹交给别人 / 公开发布之前，想确认"对方打开看到的是空树"；
  • 换了一份工作区副本、或换了 me.json，想从零开始（旧树还躺在浏览器里）；
  • 导入"全量包"之前，不想让旧数据混进来（也可以先导出备份再清）；
  • 排查"数据看着不对"（怀疑浏览器里存的与包不一致）。

怎么清：在那个页面按 F12 打开控制台，粘这两句、回车：

const { clearAll } = await import('/src/persistence/index.js');
await clearAll();
location.reload();

跑完会自己刷新成空树。它清掉的是： 全部节点（只留根）+ 全部副页（整页删掉）+ 全部训练计划； 不动你的账户、设置与抓取来源（与设置页 Ctrl+点「🗑 清空」完全同一件事， 只是不用点界面 —— 想点界面就走那一条，效果一样）。

想彻底回到"出厂状态"（连账户 / 设置 / 来源注册表都回默认， 用来模拟"第一次拿到这份文件夹的人"）：在上面两句之外，把浏览器那点小配置也一起清掉 ——

const { clearAll } = await import('/src/persistence/index.js');
await clearAll();          // 树 / 副页 / 计划（IndexedDB）
localStorage.clear();      // 剩下的本机小配置（宽度、页签、视图态…）
location.reload();
⚠️ 不可撤销：这些一跑，浏览器里那份就没了（磁盘上的 me.json 不受影响， 它仍归那个 .bat 或设置页的「🔐 登录态」管）。 要留底就先「📤 导出全量包」（它含设置 / 来源注册表 / 账户 / 信任表）， 清完再「📥 导入」回去。 想"连磁盘也一起清"：先跑 .bat（选 1 / 2 / 3 级），再在页面里跑上面那几句 —— 顺序无所谓，两条都要做。

⚠️ 只跑 clearAll()（不清 localStorage）时，账户还在 —— 想验证"新用户看到什么"，看的是一个没有用过这应用的浏览器；同一个浏览器里账户是应用数据， 不会被清磁盘或清树的那几下带走。

十八·补一、设置页（⚙️）

顶栏的 ⚙️ 设置 是一个独占的一级页签（不再是弹窗）：整页按卡片排， 控件占满一列，改完即生效。

那一栏改的是什么存哪儿
🖥️ 显示 / 💾 保存 / ⚡ 性能 / 📊 统计 应用设置（每页几个、方框数、撤回步数上限、计数模式…；编辑模式在「显示」那张卡里、自动保存/定时导出在「保存」里） 进存档（AppState.settings），能撤回、跟着「完整数据导出」走
🔑 账户 / 名册 上面那半是应用账户（真源，见第十八节）；切到「名册 / 凭据」那半改的是磁盘上的 me.json（抓取脚本的配置：CF/CLIST 的 key、QOJ cookie、各站用户名） me.json 由本机主脚本读写；不进撤回历史、不随导出走（那是爬虫的配置， 不是这份数据）
💡 两件事别混：页头那句提示就是给这件事的 —— 上面是"这份数据怎么显示/怎么算"， 右下那栏是"爬虫拿什么凭据去抓"。前者改错了可以撤回，后者改错了要自己再改回来。

me.json 那一栏的「登录态」块里，每一行一个「🔎 探活」：一键问抓取侧"这份凭据 还有效吗"（与脚本用同一套判据），不用等下一次抓取才发现过期。

十八·补二、体检 / 需求（🩺）

这一页的数据来自你导入的那个包（包顶层带着两份报告），不联网、不重算 —— 所以"重建一次包、再导入"之后它才会更新。

字段体检

每一行是一个"某类节点上的某个字段"，按四档看：

  • 已填：有值；
  • 缺：该有却没有（红）；
  • 豁免：有证据表明"实际没有"（比如上游根本没这场）；
  • 多半拿不到：注册表里标了"追也多半追不到"—— 也不算缺， 与「豁免」并列。

页头那句小结会把"真缺多少 / 豁免多少 / 多半拿不到多少"分开念，别把后两档当成欠账。

🩺 小结（最左边那一栏）

这一栏是"这一页到底想说什么"：页头那句结论 + 与上次体检比 （哪些字段变差了（红）/ 变好了（绿），带 Δ 数字）+ 缺得最多的几行 + 最划算的几条需求。判断"这次重建是变好还是变差"就看它，不用自己对数字。

⚠️ 比的是随包的快照：没重新出包、没重新导入，这一栏不会变 （"没有可比的上一次"时它会直说）。

原料需求

把"缺的格子"翻译成"要去抓什么"：每条需求带着可直接粘贴的命令和一行"为什么缺" （"没抓到" / "上游没有" 是两回事）。按来源分成几组，同一条命令的合并成一条。

💡 什么时候该来这页：① 觉得"某类数据怎么总是空的"； ② 想补一批数据但不知道从哪一步开始。按需求上的命令跑完，再重建一次包导入，这一页就变干净了。

十九、数据是怎么存的（大白话）

这一节回答一个最容易被绕晕的问题：我没填过的值，为什么树上会出现？ 答案是这个应用为每个字段存了三样东西，各管一件事。

一个字段的三层

  • ① 你在树上看到的值 —— 只是"显示"，它随时按你现在的查看身份重新算；
  • ② 缓存值 —— 应用内部记的"当前值"，老数据基本只有这一层；
  • ③ 来源清单 —— 谁说过什么：手改说的、榜单说的、脚本说的、算出来的。 同一个字段可以躺着好几条互相矛盾的说法，这很正常。

看到的值就是从 ③ 里挑一条当代表（挑的规则见下）。 如果 ③ 是空的，那就是没有出处 —— 面板会如实写「没有来源值」， 并说明是哪种情况：派生字段（值是算出来的）还是常规字段（值是新建节点时的默认值）。 ⚠️ 面板不会再去拿 ②（缓存字段）当"出处" —— 那条回退已经删了： 应用里的数据都是新导入的，来源层总是有值。

多个来源打架时，谁赢

按顺序比，先比出来的赢：

  1. 你手改的（最高 —— 你自己填的永远优先）；
  2. 你点过「优先」的那个来源（见下面三个按钮）；
  3. 来源类型：手改 > 权威榜单 > 脚本 > 算出来的；
  4. 同类型的等级（每个来源自带的可信度分数，由来源/插件声明）；
  5. 时间新的；
  6. 全都一样 → 先来的赢（所以显示是稳定的，不会每次刷新都换）。

来源面板上的那几个按钮

  • 优先：以后这个字段尽量用这个来源说的话（只要没有手改压着它）；
  • 不用：这条不采用（可恢复，不会删掉，只是不参与挑选）—— 注意只有"还有别的可用值"时才给这个按钮，最后一个留在场上的值不许被踢掉；
  • 恢复：把之前标「不用」的放回来。
  • 真删：把这条值从来源层里移除（只给手改值： 你自己改的那些，以及带 🌐「所有人共用」的那些 —— 所以点完 「转成所有人共用」也删得掉；队友账户的手改值不给，榜单/脚本抓来的值也不给）。 能撤销。它和「不用」不是一回事：「不用」只是标记（值留着留痕、随时可恢复）， 「真删」才是真去掉。
  • 另外，这个字段设过「优先」时，面板底下会多一个 取消偏好：退回按来源类别/等级自动选值。

面板顶部那句"理由"就是它为什么选中的大白话（例如「手改优先」「权威榜单优先」「唯一来源」）。

题目「AC 时间」怎么取（设置 → 📊 统计）

一道题可能被训练很多次（间隔很久）。默认的规则是取最早 —— 也就是"第一次 AC"， 于是后面几次重训在「训练强度追踪 / 最近 AC 题目列表」里就看不见了。设置页那一栏可以换：

  • 取最早（第一次 AC）：默认，与老行为逐字相同；
  • 取最近（最后一次 AC）：Heatmap / AC 列表落到最后一次；
  • 取「截断时间」之后的最早一次：填一个时间（8 位 = 到天、12 位 = 到分、14 位 = 到秒， 分隔符随便写），取不早于它的那些里最早的一条； 这道题一次都没有（全在截断之前）⇒ 取它最后一次 AC。
  • 取「截断时间」之后的最早一次，并忽略截断前的所有提交：在上一档的基础上， 早于截断的提交整体不算 —— 不算提交、不算 AC、也不算"最新提交" （树上那些行会变淡，但仍在、仍能点开）。截断之后一条提交都没有 ⇒ 这题回到「未使用」。用途：重复利用训练资源 —— 早先过过的题重新练时，让它重新回到待办里。

⚠️ 第 4 种是"会改行为"的那一档（前三种只改"树上那格 AC 时间显示哪一条"）： 它同时管着这题过没过（状态2）、AC 时间、最新提交，也会影响统计与判重模式下的「组那份」。 被忽略的提交不写任何标记（纯按条件算出来的）⇒ 随时换回前三种就完全复原。

它管的是整条口径：树上那格「AC时间」、训练追踪、判重模式下「组那份」全都跟着一致。 改完点保存会当场重算一次（大表上约几十到一百多毫秒）。

哪些值是"算出来的"，为什么不能直接填

有几类字段是应用自己算的：状态2、完成状态、AC 时间、最后提交时间、XCPC 难度。 它们由子节点或通过率推出来，所以编辑弹窗里不记手改（记了也会被下一次重算冲掉）。 其中有两个允许你按一下覆盖自动结果（这是"你的决定"，不是"你填的值"）：

  • 题目的状态2：待写 / 赛时通过 / 忽略（"忽略"= 这题别算进统计）；
  • 比赛/系列/平台的完成状态：忽略。

只有「我处理了吗」（状态1）例外：它是用户输入，按登录账户算， 与"在查看谁"无关。

存档里到底存了什么

点「完整数据」导出的文件（含主树、副页、设置）里，会带走这些东西：

  • 整棵树：节点、父子关系、每个字段的来源清单（含"这是谁说的"）、 每个节点的"创建归属"（谁让它出现的）；
  • 账户注册表（账户名、性质、映射、活跃开关）与"登录/在查看"两个指针；
  • 来源注册表与优先级设置（你说的「优先」就是它）。

不带走的：撤回历史（导入后从零开始）、当前打开的是哪个页签、 "展开到哪一层"这类纯界面状态。

💡 为什么值得信任一份导出文件：它能把以上全部原样搬回来 （包括"这条通过率是榜单说的、那条是你手改的"）。所以做实验之前先导出一次， 是这里最省事的安全网。

撤回能退回什么（在设置面板里点，没有快捷键）

每一步"改动"都能一步步退回：改字段、增删/移动/复制节点、改标签、副页操作、 账户的新建/改名/映射/停用/删除、切换"在查看"、跑一次归认、清空数据。 按一次只退一步；退到头会提示没有可撤回的了。 （导入整库文件、以及"展开/勾选"这类纯界面动作不进撤回历史。）

二十、看着不对时，按这个顺序查

遇到"这不对吧"的时候，照这个表走一遍，基本能自己定位到是哪一类问题。 每一步都只用到界面上能看到的东西。

你看到的现象先看这一处最可能的原因
某个字段的值不是我填的 / 突然变了 编辑弹窗里字段下面那句来源，点开 ⓘ 看清单 这个字段本来就该有多条来源，现在挑中的是别人或榜单那条。 想固定成你要的：找到那条点「优先」。
改名 / 删除 / 加标签被拒绝 顶栏那个账户标记有没有写成 「👁 <账户名>（只读）」 你现在"在查看"的是另一个账户。切回自己的账户即可（见十八节）。
统计数字和树上显示对不上 信息栏最后一句的"口径"，以及顶栏在查看谁 统计按"在查看"的账户算；换了人看，数字本来就该变。 另外「我处理了吗」仍按登录账户算。
导入完了，但树上看不到变化 打开那道题的 ⓘ 来源清单 导入只往"来源清单"里加一条，显示值由挑选规则决定 —— 新来的可能没被选中（比如它是脚本、原来那条是榜单）。
标签管理里是空白行或删不掉 先刷新一次页面再试 老版本导入留下的坏数据，打开时会被自动修回来；刷新后仍不对，就把「你点了什么 + 屏幕上出现的提示原文」记下来。
值那一格写着「没有来源值」 —— 正常：派生字段的值是算出来的、常规字段的值来自新建节点时的默认值 —— 面板里会写明是哪一种（见第十九节「三层来源」）。
改了东西，界面没反应 / 重启后没了 见十七节常见问题 多半是浏览器还在跑旧版本（敲 __ACM_BUILD__ 看一眼版本号）。
💡 出问题时的三步安全动作： ①先「导出完整数据」留个备份；②刷新页面（Ctrl+F5）再试一次； ③还是不对，就把"你点了什么 + 屏幕上出现什么（提示原文）"记下来。 数据本身很难被弄坏：导入只加来源、不改写你没让它改的东西， 而且大部分改动能退回（设置面板 → ↩️ 撤回，没有快捷键）。

二十一、名词小词典

界面/文档里的词大白话
来源 / 值级来源"这条数据是谁说的"：手改、榜单、脚本、还是应用自己算的。
来源清单同一个字段上所有说法的集合（可以有好几条互相矛盾的）。
挑选 / 投影从清单里按优先级挑一条作为"现在显示的值"。
客观值不属于任何账户的值（例如榜单算出来的通过率）。面板上标「· 客观」。
归属 / 这是谁的这条值算在哪个账户名下。导入时靠"映射"认出来。
线索记录里能指出"是谁"的那一列（如 QOJ 的"提交者"）。
映射账户里写的「源 : 字段 ＝ 值」，用线索来认账户。
归认导入时拿线索查映射表，把记录记到某个账户名下。认不出会报出来，不会瞎猜。
手改你在弹窗里真的输入过、而且值确实变了 —— 两条都成立才留记录。
派生 / 算出来的由子节点或通过率推出来的值（状态2、完成状态、AC 时间、难度）。
覆盖你对"算出来的值"按下的决定：待写 / 赛时通过 / 忽略。
缓存值应用内部记的"当前值"，老数据只有这一层。
没有来源值这一格没有出处：要么是派生字段（值是算出来的），要么是常规字段（值来自新建节点时的默认值）。见第十九节。
身份键导入包的"这道题是谁"的编号，用来避免同一道题被导两次。
导入包（crate）爬虫整理好的一个文件，里面是"要写进树里的记录"。
只读 / 在查看用别人的眼睛看数据的状态：这时手改被拒，导入照常。
活跃 / 停用账户的开关。停用只是先收起来，数据一个都不删。
口径信息栏最后那句：现在这些数字是按哪个账户算的。
合成节点 / 合成标识树上给一批原料当「组头」的真节点；它的身份是合成标识（synthKey，界面显示 🧩）。见第三节。
所属合成节点原料上的指针（ownerSynth），写着某个合成标识 —— 填了它就归入那一组。归入/解绑在判重整理页做。
性质分类 / 年份 / 赛季 / 地区四个可空字段，只用于分区与筛选。见第四节。

二十二、训练计划

在某一个副页上，「总览统计」下面、树上面，有一条训练计划栏。一条计划 = 一个题集 + 一个目标： 题集默认就是那个副页里的题（第九节），也可以改成"树上某个范围 + 条件"（见下），完成情况每次现算（不存快照）。

怎么建一条计划

  • 计划栏上点「＋ 新建计划」：填名字、选一个副页当题单、填开始时间、定目标。
  • 目标只填一份（例如「每天 3 强度」或「每周 2 题」）。看图表时可以随时换粒度 （日 / 周 / 月），目标会按「每天配额 × 这一期的天数」自动折算 —— 你填的那个数不会变。
  • 计划的题集 = 那个副页里的全部题（副页里放了整场比赛，它下面的题也算）。 所以在哪一页挑题，是「副页」那一层的事，计划这边不再筛一遍。

题集的规则（详细页 → ⚙️ 计划设置）

先记一条总规则：题集永远只从这条计划绑的那个副页里取（副页 = 你的题单池）。 在这之上只有两个旋钮：范围根（留空 = 整个副页）与条件 （难度/标签/平台）。想做"CCPC 2023 的银牌题"，给个范围根 + 勾上档位就行， 不必一道道手工加 —— 而且以后新导入的比赛只要落在这个范围里，就自己进来 （前提是它也在那个副页里：副页里放着整场/整个系列时，它的子树长大 ⇒ 新题自己跟上）。

  • 范围根：留空 = 整个副页（系统自动用"超级根"，也就是 "就用这个副页里的题"）。想缩小：在树上或这个副页里把要的节点 行上那颗 ○ 点亮，回设置里点「⭯ 取当前选中」把那份标记 存成范围根（勾了父又勾了子 ⇒ 只算父那一棵）。「清空」回到整个副页。 ⚠️ 这是一次性的快照：存好之后别处怎么点 ○ 都不会改这条计划的题集， 想改就回副页再标记一次、再点「取当前选中」。 ⚠️ 范围根必须落在这个副页里才有用（题集只从副页里取）—— 全是副页外的根时， 界面上会写"这些范围根不在这个副页里"，题集自然是 0。
  • 题集条件（难度区间 / 标签 / 平台 / XCPC 档位）：不勾 / 留空的那一维 = 不限。 它一直生效（哪怕没选范围根，也是在"整个副页"里按它筛）； 改它 题集就变（强度、达成、两张图全跟着变）⇒ 记得点「💾 保存计划」。 判据与「📋 按条件挑题」是同一份。 ⚠️ 它与下面那张列表的「列表筛选」不是一回事：那个只看这一屏，不改题集。
  • 这套规则现在算出来什么，卡里直接写着：改任一处，下面那句就会跟着变 —— 这条计划的题集 = 副页「X」里的题 ∩ 子树「CCPC 2023」 ∩ 题集条件：档位 银牌… ⇒ 现在 111 道。 （没设范围根时，中间那段"子树"不会出现。）
  • 筛选模式：计划这边没有这一档 —— 范围是一次性取好的 （见上一条），计划不会因为你在别处点 ○ 而变。统计页那张「筛选模式」是另一套东西 （它的主语是主树节点），与计划无关。
  • ⚠️ 「取当前选中」是一次快照：它记下的是点那一下行上那颗 ○勾着的东西 （主树上的勾 + 当前这个副页里的勾）；之后改勾选不会自动改计划， 要么再点一次，要么直接改条件。
    两条要知道的：① 勾了父又勾了子 ⇒ 只算父那一棵（子那棵本来就在父里，题集一样）—— 界面会写明"你勾了 N 个、哪几个没单列"；② 副页页签上那颗 ○ 不算， 那是「整页映射覆盖」的意思、归下面的筛选模式管（想在整页范围内取题，就把筛选模式选成 「仅选中副页映射覆盖」）。
  • 副页仍然要绑一个（它决定这条计划显示在哪个副页上、以及「去题单页」去哪）； 范围型计划的题集与那个副页里有什么无关。

这条栏在哪儿出现

只在计划绑的那个副页上出现：主页（主树）上没有这条栏；切到某个副页，就只看到绑到它的计划 （别的副页的计划不在这一页上占地方）。副页上还没有计划时，这条栏给一句提示 + 「＋ 新建计划」—— 新建的计划默认就绑当前这个副页。

栏上看得见什么

  • 每一行：计划的这一期（实际 / 目标）与累计；点「▾ 收起」折起明细。
  • 整条栏也能收起（点「▾ 收起」）—— 折叠状态只存在本地，不进数据、不进导出包。
  • 明细里逐期列出题数 / 总强度 / 目标 / 是否达标，越新的期排得越靠前； 并如实报一句「N 道题没填难度，不计入强度」。 （没有 AC 时间不再提醒 —— 那很正常，那些题只是不进任何一期。）
  • 「📖 完整信息」进详细页；「✖」删计划（题单页会留着）。 题单页被删掉时，计划还在，行上会写明「题单页已删除」。

训练强度怎么算（映射表）

  • 每道题的训练强度由它的难度查一条曲线得来。表在设置 → 🏋️ 训练强度里： 可以有好几张有名字的表（例如「日常」「集训」），计划引用其中一张。
  • 一张表里填两组控制点：每个点是「通过率 / 数值难度取它时，强度是多少」 （不是"不超过它就算这一档"），点与点之间默认按指数曲线相接（也可选线段 / 平滑曲线）。 XCPC 难度那一组通过率越低越重： C / R 那一头约 113，一路降到签到的约 1.3； 难到一定程度就不再涨了（那一点写着「0.031%及更小」）。 数值难度那一组出厂是 2600 取 10、每差 400 分强度翻倍， 最低 1（CF 大约 1271 分以下都一样轻）、最高 4000 及以上（再高也一样重）。
  • 没填难度（连通过率/难度都没有）的题强度记 0 —— 它不计入任何强度合计（热身赛那类没有难度数据的题不会把账抬高）； 计划那一行仍会提醒你「N 道题没填难度」。 题数那一侧照旧算（"这道题做过"是事实）。
  • 这一栏的表自带保存按钮（改完点「💾 保存这张表」），与底部那个「保存设置」不是一回事。

点「📖 完整信息」进详细页

计划那一行上的 「📖 完整信息」 会开一个详细页 （与"节点详页"同一个机制：上面那条独立的页签栏、可以同时开好几个、各自关掉）。里面有四块：

  • 📄 题单来源：这条计划的题集是从哪来的、一共几道题 —— 副页型的写"副页「X」里的全部题"，范围型的写"树上范围（N 个范围根）…"； 范围根不存在 / 一个都没选时，这里会如实写一句（不会假装是 0 道题）。 「去题单页」会回到主视图并切到那个副页（一步到位，不用你自己再点页签）。
  • 📋 题目列表：逐题列出题号 / 题名 / 难度 / 状态2 / AC 时间 / 强度 （难度带自己的颜色；没填难度的强度记 0 并标出来）。 开头那行写着「列表筛选：」—— 它只决定这一屏列出哪几行 （不动题集、不进数据、不进包；要改题集请回「计划设置」的「题集条件」）。 一共四行： XCPC 难度（多选芯片，按难度从易到难排 —— 签到在最前、 末了还有一个「未填写」；芯片上的档名也带各自的颜色）、 数值难度（一行：下限 / 上限）、 标签、平台 / 赛系；再加快捷的关键字与状态2。 还能排序（AC 时间、强度、难度、题号）与选每页几条； 也能翻页、收起；点某一行就跳到树上那个节点。 （标签与平台芯片是从这个题集里现收的，所以只有这里真出现过的才列。）
  • 📊 状态 × 难度：与「数据统计」页一模一样的那张网格 （同一份渲染：行 = 状态2、列 = 难度档、列头的难度名带自己的颜色、格底同色、带合计）。点某一格就把上面的题目列表筛成那一批。
  • 📈 每期完成情况：这一整块（表 + 下面那两张图）共用同一个时间区间 —— 上面那段范围筛选一改，表和两张图一起只算那一段（「全部」清掉）。 表按期列出题数 / 总强度 / 目标 / 是否达标，越新的期排在越前面； 表按 3 列排（列优先：一列读到底再换下一列），一页就是 3 × 每列条数（默认 3×12 = 36 条）—— 一次能看很长一段； 范围筛选用的是「训练强度追踪」那一套（起止各三个下拉：年 / 月 / 日，再点「确定」）； 按了「确定」之后，那段时间就是期窗口本身 —— 拉到计划开始之前、或拉到未来也照排 （那些期是空的，一眼能看出"哪几天荒了"）；点「全部」回到计划开始到现在。 也能收起、翻页。
  • 点某一期 ⇒ 看那一期做了哪些题：表格里点某一行，或者干脆 点图里某一根柱子 / 折线上某一个点，这一块下面就列出那一期做完的题 （题号 / 题名 / 难度 / 状态2 / AC 时间 / 强度），点题就跳到树上 —— 与「训练强度追踪」一个意思。 表和图说的是同一件事：选中的那一期两边一起高亮；点「✖ 收起」放掉。
  • 图上看得到数：每根柱子顶上写着数值，折线的点上也标了累计值； 鼠标悬停在柱子/点上会写清「这一期/累计完成多少、目标多少、做了几题、达没达标」。
  • 🏋️ 当前强度表：这条计划引用的那张强度表长什么样 —— 每个 XCPC 档位、 每段数值难度各算多少强度、没填难度记 0，都能在这儿看一眼（只读，默认收起）。 要改就点那块里的「⚙️ 去设置里编辑」，直接跳到设置页那一栏。
  • ⚙️ 计划设置：名字、起止时间、目标（口径 + 值 + 基准粒度）、 「算做完」的状态2 是哪几档、强度按哪个难度源、引用哪张强度表， 以及题集来源（副页里的题 / 树上范围 + 条件）与筛选模式 —— 后两样见上面那节「题集还能从"树上范围 + 条件"来」。改完点 「💾 保存计划」。

💰 强度总账（详细页最上面那块）

  • 已写 / 总训练强度：分母是题单里填了难度的那些题的强度之和 （还没做的也算进去；没填难度的记 0、不进账）， 分子是其中已经做完的那些。
  • 目标训练强度：就是计划里填的那份目标，折算成每天多少 （"每周 20 强度"⇒ 显示约 2.9 / 天）。
  • 推荐训练强度：填了结束时间才算 —— 它把"还差的强度"按剩余天数摊平， 意思就是"恰好按时完成每天要做多少"。没填结束时间就给「—」，不会瞎猜。
  • 预计完成（按目标）：按上面的目标速度，从今天起还要几天、哪天能写完。

「每期完成情况」那两张图

  • 图① 累计：从计划开始那一期起逐期累加的折线，配一条斜直线目标线 （斜率 = 每期目标）—— 一眼看出"追不追得上"。
  • 图② 每期：每期各自的量（柱），配一条目标线 —— 一眼看出"哪几期偷懒了"。
  • 两张图各有自己的查看粒度（默认：折线按日、柱状按周）， 随时可切日 / 周 / 月 / 整段；切换只改"怎么看"，不动计划的执行粒度、也不改你填的目标值 （目标按"每天配额 × 期天数"折算）。
  • 每张图都能单独收起，还有一颗 「⇅ 换序」把两张图上下对调。 图上的文字与按钮都做得小巧（与块里那句灰色说明同字号）；横轴上的期标签 遇到放不下会自动换行，还挤就横向滚动 —— 不会叠成一团。
  • 目标口径选"题数"时，两张图的纵轴就是题数（同一张图的形状不变）。
