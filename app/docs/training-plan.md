```js
  end: null,                   //   结束时间可选；null = 一直有效

  goal: {                      // ★ ⑬ 目标：按**执行粒度**存**一份**值（㉑；其他粒度折算，见 §4.4）
    mode: 'intensity',         //   'intensity'（训练强度）| 'count'（题数）
    per: 'day',                //   **执行粒度**（⑳，默认 'day'）：'day' | 'week' | 'month'
    value: 3
  },

  statuses: [3, 4],            // ④ 算"做完"的 status2 集合

  intensitySource: 'xcpc',     // ⑪⑯ 这计划按哪个难度算强度：'xcpc' 档位 | 'cf' 数值（**计划自己选**）
  intensityTableId: 'ti_1'     // ⑪⑮ 引用**全局若干张有名字的强度表**里的一张
}
```

**刻意不放进形状**：折叠态（→ 视图态 `state.view`）、达成度与各期完成情况（→ **现算**，⑦）、题单本身（→ 副页）。

## 4. 口径

### 4.1 题集怎么来（③㉒㉓：**筛选在更靠前那一步，计划侧不再筛**）

```
题集 = 计划绑的那个副页 virtualIndex 走出来的**全部真实 P**（C 就展它子树）→ 按 id 先去重
       （**计划里没有 filter** —— 用户："不用再在副页上筛选"）
```

**筛在"题单形成"那一步做完**（更靠前），两条路（㉓）：

| 路 | 怎么做 | 仓里有没有 |
|---|---|---|
| **自动**（"要再写点东西"） | 挑题（条件）→ 复制进副页 | **已有一半**：`ui/G_modal/G5_actions.js:promptTodoProblemSheet`（按**显示口径 + 查看范围**挑 `status2∈{0,1,2}` 或 `status1===0`）→ `core/ops/page.js:batchCopyToPage`（含冲突检查 / 重复跳过 / 可递归）。**要补的是**：① 挑题**条件**扩开（维度复用检索页那套：难度/标签/平台/系列/状态…）；② 允许**新建副页** |
| **手动**（"不怕麻烦手动也行"） | 自己在副页里加/删题 | 现成的副页编辑那一套（`G4_copy.js` 等），一个字都不用写 |

⚠️ 副页是**投影**：子树要从 `virtualIndex[*].children` 走、再经 `refId` 回真实节点，
**别拿主树 `childOrder` 去套**（页内 id 在 `state.nodes` 里查不到）。
⚠️ **重复题不会翻倍**：`batchCopyToPage` 已经会检出"已在本页"的冲突并跳过（`skipDuplicateCheck`），
所以"再按条件补一次"是**安全的增量**（只增不改）。

### 4.2 达成度 / 各期完成情况

```
每个 P：s2 = viewDerivedDisplay(state, node, 'status2')      // 按「查看范围」投影读，与树上同一读口
        t  = viewDerivedDisplay(state, node, 'acTime')
        w  = 强度（§5）
做完 = statuses.includes(s2)
期（周）= 由 `t` 落到哪个周（周切分见 §10 ③）
达成 = 该期做完的 { 题数 | Σ强度 } / goal.value
```

**两层去重**（③ 那句"去重模式自然解决"落在第 2 层）：

| 层 | 是什么 | 用哪一份 |
|---|---|---|
| 结构层 | 同一道题在页里被引用两次 | 按真实节点 id 去重（与开关无关） |
| 组层 | 同一道题的**不同来源副本** | 判重模式下走现成的 `groupKeyOf` / `dedupRepresentatives`（一组一条） |

⚠️ 组层**跟整体计数口径走**（`settings.stats.countMode`）——与网格表 / 热力图 / AC 列表**同一把尺子**。

**已实现的语义**（`core/trainingPlan.js:planProgressOf`；判据 `src/test/trainingPlan.test.js`）：

| 项 | 语义（**别在界面侧另立一套**） |
|---|---|
| 每期的 `count` / `intensity` | **只算"做完的"**（`status2 ∈ plan.statuses`）—— 两张图与目标都读它 |
| 每期的 `countAll` / `intensityAll` | 这一期**有 AC 时间**的全部题（含没做完）—— 用来显示"这期共 N 题" |
| **没有 `acTime` 的题** | **不进任何期**，单独计数 `undatedCount`（界面要报出来，别静默丢掉） |
| **没填难度**的题 | ★ **强度记 0**（`v9.1.45`，用户第 12 轮："未填写的不计入 因为有热身赛等"⇒"强度为 0 就行了"）；单独计数 `unknownDifficulty`（界面要提醒） |
| 组层去重 | `dedupRepresentatives`（`plain` 原样 / 判重同组留一条）；★ **字段值必须走显示口径（组那份）**，否则"代表那条"会把成绩抹掉 |
| 目标 | `dailyQuotaOf` / `periodGoalOf`（㉑ 只存一份、按"每天配额 × 期天数"折算；月键是 `YYYY.MM`） |
| 期键 | 日 `YYYY.MM.DD` / **周 = 那一周的周一**（周日归前一个周一）/ 月 `YYYY.MM` / `all` |

### 4.4 期与粒度（⑲⑳㉑：**两个粒度互相独立**）

★ **要分清两个粒度，别把它们焊在一起**（用户 2026-10-13："**注意实际正在执行的计划的粒度与看图表的粒度相独立**"）：

| 粒度 | 是谁的 | 默认 | 住哪 | 谁来读 |
|---|---|---|---|---|
| **执行粒度** `goal.per` | **计划的属性**：目标填在这个粒度上、外层条按它显示进度、达标判定按它 | **日** | `state.plans`（**数据**，进包） | 外层条、达成判定 |
| **折线图查看粒度** | 图①（累计）**自己**的 | **日** | **视图态**（按计划记住） | 图① 的 x 轴与斜直线目标 |
| **柱状图查看粒度** | 图②（每期总和）**自己**的 | **周** | **视图态**（按计划记住） | 图② 的 x 轴与水平目标线 |

```
粒度（day | week | month | all）⇒ 决定"一期"多长：日 = 当天、周 = 自然周、月 = 自然月、all = 整段一期
每个 P 落进"它 AC 那一期"（`t` = acTime 所在的那一期）
各期统计 = { 题数, Σ强度, 难度分布 }              ← 列表 / 两张图都从这一份来（**按期分组后再各自聚合**）
某粒度的每期目标 = 每天配额 × 这一期的天数         ← 每天配额 = goal.value ÷ goal.per 的天数（㉑ 折算）
```

- ⚠️ **两个粒度独立**：把柱状图切到"月"**不会**改掉执行粒度，也**不会**改掉另一张图的粒度，
  更**不会**动 `goal`（用户填的那个数一个字都不变）。
- ⚠️ **执行粒度住数据、查看粒度住视图态**：查看粒度**不进 `state.plans`、不落 `nodes`**
  （落了会随包发给别人、也会污染按代缓存）——与折叠态同一套规矩。
- ⚠️ 折算会出现小数（"每天 3 强度" ⇒ 每周 21 没问题；"每周 20" ⇒ 每天 2.86）⇒
  显示保留一位小数、**判定达标用折算后的值**（别四舍五入到整数后再比）。
- ⚠️ 两张图的 y **必须同源**（同一张强度表 + 同一个 `intensitySource`），只是 x 的粒度不同。
- **"all"（整段当一期）**：只对**图表**有意义（列表本来就不分期）⇒ 见 §10 ①。

### 4.5 期与"开始时间"的关系

`start` 必填（§10 ④），**第一期从 `start` 所在的那一期起算**（不是从"整周的第一天"另起）；
`end` 为空 ⇒ 一直排到"最后一期 AC 的题"那一期（图 x 轴到那儿为止）。

### 4.6 性能

达成度**必须**喂现有 `countPass` / 派生表那一份，**不许自己扫全表**（`computeGlobalStats` 一趟 ~100ms，
它已经在"延迟一拍"那一侧）；新面板重画时**只算当前要显示的那几期**，别一次算全部历史。

## 5. 训练强度（⑪⑮⑯⑰，**新机制**）

> ★ **`v9.1.38` 重定过口径**（用户 2026-10-13 第 5 轮）：强度**不再是台阶表**，而是
> **一串控制点 + 点之间相接**；XCPC 侧的横坐标换成**通过率**（原来按档位名查，且**数值是反的**：
> C+ 只给 1、金牌+ 给 16 —— 最难的最轻，第 5 轮纠正成 C/R 最大）。
> ★ **`v9.1.42` 又重定一次**（用户第 9 轮）：XCPC 侧的**值**不再按"每档 ×1.2"排，
> 改成"**通过率折算成等价的数值难度，再走数值那条式子**"——于是两条曲线**共用同一条式子**。

- **是什么**：每道题 → 一个强度值；计划的"强度目标 / 强度曲线"都从它来。
- **怎么算**：题目难度 → **查曲线**。难度源**由计划自己选**（⑯）：
  · `intensitySource: 'xcpc'` ⇒ 横坐标 = **通过率**（`ratio` 字段，百分数）；
    读不出 ratio 但有档位 ⇒ 用那一档通过率区间的**中点**近似（`xcpcBucketOf` / `XCPC_THRESHOLDS`）
  · `intensitySource: 'cf'` ⇒ 横坐标 = 数值难度（`difficultyValueOf`）
- **曲线 = 控制点 + 相接方式**（`core/trainingPlan.js:intensityAtPoints` —— **两条曲线共用的唯一一份**）：
  · **数值侧 = 一条式子**（`v9.1.40`，用户第 7 轮："以 2600 取 10 为基准，每差 400 分强度翻倍；
    再对 1 取 max，大概在 1271 前生效"）⇒ `max(1, 10 × 2^((cf−2600)/400))`
    （`core/trainingPlan.js:cfIntensityAt`；触底点 = 2600 − 400·log2(10) ≈ **1271**）。
    ★ **两端都封口**（下限 1 从 `v9.1.40` 起，上限 `v9.1.42` 起）：式子里就
    `min(CF_INTENSITY_MAX, max(1, …))`，**不靠查表兜底**（查表那条路只在"表被手改过"时才可能不同）。
    ⚠️ **上限取 4000**（用户第 9 轮："数值难度的强度计算上限也是 3500，3500 以上与 3500 同强度"；
    第 10 轮："其实上限改成 4000 也行"）⇒ `CF_INTENSITY_MAX = 113.14`。
    **真数据里 cf 的最大值正好是 3500**（326 道，一道都没更高）⇒ 这个数一动，
    **数值侧的实际结果不变**，变的只是通过率侧难端的天花板（见下）。
    控制点 = 把这条式子**每 400 采样一点**（`cfIntensityPoints`：1271 → 1400 → … → 3800 → 4000）。
    ⚠️ **指数段相接 ⇒ 点之间也恒等于式子**，所以采样放粗到 400 也不丢精度（旧版用「直线逼近」时必须密采）。
    ⚠️ 用户举的"1600 取 1.25"与式子对不上（严格算 **1600 → 1.77**、**1400 → 1.25**）——
    但他给的"1271 触底"正好是式子的解 ⇒ 以式子为准（已在报告里点明这一处）。
  · ★ **XCPC 侧 = 同一个式子 + 换个横坐标**（`v9.1.42`，用户第 9 轮）：先把通过率折算成
    **等价的数值难度**（`core/trainingPlan.js:ratioEquivCfAt`），再喂给上面那条式子
    （`xcpcIntensityAt`）。折算是一条**横轴取 `log2` 的两段折线**：
    `r ≤ 16%` ⇒ `2200 + 200·log2(16/r)`（每折半 +200 分）；`r ≥ 16%` ⇒ `2200 − 300·log2(r/16)`
    （每翻倍 −300 分）；两者都**对上限封顶**。
    ⇒ 于是容易端**到不了 1**（通过率 100% ⇒ 等价 ≈1407 分 ⇒ 强度 **1.26**；式子那个"触底 1"要等价 1271 分
    = 通过率 400%，不可能），难的一端封顶 ⇒ **113.14**（等价 4000 分，通过率 0.03125%）。
    ⚠️ **用户明说这套对应"不会明写，只是数值一致"** ⇒ **只住代码里**（`ratioEquivCfAt` 一处），
    **别印到界面文案 / `docs/guide.html` / 报告里**。
    ⚠️ 折算出来有**两个点不在档位边界上**，但都必须**单独当控制点**（`xcpcIntensityPoints` 会带上）：
    · **拐点 16%**（式子在这里换斜率）—— 不加它 `[15,20]` 那段最多偏 **1.41%**；
    · **"到顶"点 0.03125%**（式子在这里撞上限）—— 不加它 `[0.11,0.22]` 那段会把封顶平段插成斜坡。
  · ★ **横轴取对数**（`v9.1.43`，只通过率侧用；`intensityAtPoints(..., logX)`）：
    通过率侧的口径本来就定义在**对数刻度**上（"每折半 +200 分"），强度于是是 `C·r^(−p)` 这种**幂律**
    —— 在 `log r` 上正好是直线 ⇒ 取对数后**查表处处等于式子**（实测最大偏差 0.79%，全部来自
    "控制点只存两位小数"）。**不取对数**只能逼近：顶段跨 3.5 倍时实测差 **10%**（单测有反证）。
    ⚠️ 数值侧**不取**对数（那条式子的自变量是分值本身，指数连接已经恒等）。
    ⚠️ 表里有 ≤ 0 的横坐标（用户手加的点）时，**整条曲线退回原值横轴**（`log(0)` 没法算，如实降级）。
  · 点之间：`mode: 'exp'`（**指数段**，默认）| `'line'`（线段）| `'smooth'`（单调三次 PCHIP）。
    ★ **指数段**（`v9.1.41`，用户第 8 轮：「我希望两个难度对应的强度都以**指数函数**为主，
    尽量用指数函数连接/描述整个公式」）：每段是 `v₁·(v₂/v₁)^t` ⇒ 数值侧**处处恒等于那条式子**
    （不再是「采样 + 直线逼近」）。
    ⚠️ 两端值都要 > 0（指数要求）；任一端 ≤ 0 时**那一段退回直线**（如实降级）。
  · ⚠️ 界面上**不许写「通过率 ≤ X ⇒ 强度」**（第 10 轮用户："'通过率 ≤ X' 的说法可以去掉了"）：
    这些点是**曲线上的点**（"通过率取它时强度是多少"），不是"不超过它就算这一档"的台阶 ——
    老写法会让人以为点之间是跳变的。现在每个点写成下面那样（唯一一份：`core/trainingPlan.js:xcpcPointTextOf`）：
    · 档位边界 ⇒ **「档名 + 通过率」**（`银牌 11%`）；拐点 ⇒ **`拐点 16%`**；
    · 上限那一点 ⇒ **`0.031%及更小`**（第 11 轮用户点名："它管的是这个值以及更难的"）；
    · 数值侧的末点 ⇒ **`4000及以上`**（同一个意思；`cfPointTextOf`）。
    ⚠️ 设置页那一栏**不用这两个**（它那一格是**可编辑输入框**，数字得留在输入框里）⇒ 那边只用
    `xcpcPointLabelOf` 那个**纯档名**旁注。
    ⚠️ 通过率的显示走 `utils/num.js:fmtPercent`（**三位小数**）—— `fmtAmount`（一位小数）会把
    `0.11` 和 `0.03125` 显示成同一个数（实测：两行看起来一模一样）。
  · ⚠️ **计划页那张通过率表是"列优先、最多 3 列"**（第 11 轮用户："表能不能按列连续 1~3列"）：
    `grid-auto-flow: column` + `grid-template-rows: repeat(⌈n/3⌉, auto)` + 3 列。
    行优先时 22 个点横铺成 9 列，读完一行再折回来 —— 与"越往下越难"的直觉相反；
    列优先后一列读到底再换下一列。（冒烟钉了 `grid-auto-flow:column` / `repeat(3,` / `repeat(8,` 三条。）
  · ⏳ **"更难的那一头怎么自定义"**（用户第 10 轮问的）：**现在就能** ——
    设置页那张表是控制点编辑器，可以**加一点 / 删一点 / 改值**（例如在 0.05% 处加一点给个更大的强度，
    或者把"到顶"那点的值改掉）；**难自定义的是"折算规则本身"**（每折半 +200 / 每翻倍 −300 那两个数
    写死在 `ratioEquivCfAt`）。用户已明说"自定义可能太难了，我们以后再说" ⇒ **这一版不做**。
  · ⚠️ 历史：第 8 轮曾问"能不能用**一条**式子把 ratio 与强度拟合起来"，当时以**旧的 ×1.2 台阶值**
    为靶子量过三种指数族单式，最好的一种 max 偏差也有 **18.7%**（数字见 `变更记录.md` 的 `v9.1.41` 一节）。
    **第 9 轮起这条问题作废** —— 口径已经改成"式子本身"（折线 + 那条指数式子 + 对数横轴），
    不再是"拿一条曲线去逼近一串定好的档位值"。
- **映射表：全局若干张、每张有名字，计划引用一张**（⑮）：

```js
settings.trainingIntensityTables = [
  { id: 'ti_1', name: '默认',
    byRatio: [ { max: 0.03125, value: 113.14 }, { max: 0.11, value: 60.3 }, /* … */ { max: 100, value: 1.26 } ],
    byCf:    [ { max: 1271, value: 1 }, /* … */ { max: 4000, value: 113.14 } ],  // 同上（式子采样）
    mode: 'exp'              // 'exp' 指数段（默认）| 'line' 线段 | 'smooth' 平滑
    // ★ `v9.1.45` 起**没有** `defaultValue` 了：没填难度 ⇒ 强度 0
]
```
  ⚠️ 控制点**必须按 `max` 升序**（写入口 `core/ops/plan.js:normalizeTableShape` 会排好）——
  插值按升序找段，顺序乱了曲线会来回折。
  ⚠️ 老表（只有 `byXcpc`：档位 → 强度）在写入口**迁一次**：每一档那一点落在**它自己的通过率上限**上。
- ★ **未填写难度 ⇒ 强度 0**（`v9.1.45`，用户第 12 轮："未填写的不计入 因为有热身赛等" ⇒ "**强度为 0 就行了**"）：
  `intensityOf` 读不出难度时返回 `{ value: 0, usedDefault: true }` —— 于是"已写 / 总 / 每期 / 图表"
  **全都不用改**（加 0 不影响和，不用在每个消费点各判一次）。
  · 为什么这么定：热身赛/网络赛那类题在平台侧**没有难度数据**，以前按 `defaultValue`（1）计会把总量、
    "还差多少"、预计完成日期一起抬高（用户的原话就是"因为有热身赛等"）。
  · ⚠️ **题数口径不受影响**（`count` / `byLevel` / 网格表照旧）：题数目标不看难度，"这道题做过"是事实。
  · ⚠️ 表里那个 `defaultValue`（"没填难度时按它算"）**随之删掉**了 —— 它唯一的作用就是给这些题一个
    非零权重；留着就是个不起作用的旋钮。老存档里的那个字段**读的时候不看**、也不再写出来
    （`core/ops/plan.js:normalizeTableShape` 不再输出它；不写迁移）。
  · 界面：题目列表那一列显示 `0（没填难度）`，计划栏/计划页那句提醒是
    "**N 道题没填难度，不计入强度**"。
- ⚠️ 表是**口径**：全局只有这几张，改一张 ⇒ 所有引用它的计划一起变；计划只存 id（**别存副本**）。
- ⚠️ 目标值、曲线值、列表里的强度**必须同一把尺子**（同一张表 + 同一个 `intensitySource`）。

## 6. 内层页（⑩⑫⑭）—— "跟节点详页一个意思"

**机制照抄节点详页那一套**（别新造）：`ui/tabs.js` 的**第三类 tab**（nodeinfo 就是这么做的：
自带一条独立 tab 栏、可同时开多个、按需 `ensureTabContent`）。计划页的 id 形如 `plan-<planId>`。

内层要有四块（⑩⑫）：

| 块 | 内容 | 复用 |
|---|---|---|
| A 题单来源 | 显示"本计划题集 = 📄 页名（N 题）"，给两个入口：`📄 去题单页`（看/手改）、`➕ 按条件补题`（调既有那条挑题链路） | `promptTodoProblemSheet` + `batchCopyToPage` + `EVENTS.SWITCH_PAGE` |
| B 被筛题目列表 + 统计 | 列表（像 AC 列表/检索结果）+ 统计块（**复用统计模块的设计**：柱状图 + 状态×难度网格表） | `statsCharts` / `statusGrid` / `AC 列表` 的列 |
| C 每期完成情况 | 按周列：题数 / Σ强度 / 达成率；难度分布图 + **强度曲线图** | 难度分布复用 `statsCharts`；**曲线图是新的**（见下） |
| D 计划设置 | 起止时间 / 每周目标（强度 or 题数）/ `statuses` 开关 / 强度表选择 | `settingsPage` 那套控件观感 |

⚠️ **训练强度图表（⑫⑱⑲）**：两张，**同一份强度**的两种读法；x 轴 = **期**（粒度随时可切，见 §4.4）：

| 图 | x | y | 参考线 |
|---|---|---|---|
| ① **累计**（默认粒度＝**日**） | 期（**从计划开始那一期**起） | **从计划起逐期累加的 Σ强度** | **斜直线**：斜率 = 折算到该图粒度的每期目标（第 k 期的目标 = 每期目标 × k） |
| ② **每期总和**（默认粒度＝**周**） | 期 | **该期的 Σ强度** | 每期目标那条水平线（折算到该图粒度） |

- 两张一眼分工：**① 看进度追不追得上**（累计 vs 斜直线），**② 看每期实际投入**（哪几期偷懒）。
- ⚠️ **某张图的粒度一切换，只重算它自己**（x 轴 + 目标线）；执行粒度与另一张图都不动（见 §4.4）。
- ⚠️ 两张图各自带一个粒度选择器（日/周/月/all），默认 日 / 周（⑳）。
- **显示方式 = 5 种状态**（⑱）：全折叠 / 只显示① / 只显示② / 都显示（①上）/ 都显示（②上）。
  实现（用户已选）：**每张图各自一个折叠开关 + 一颗「⇅ 换序」按钮**（同样覆盖这 5 种，控件自然、好测）。
- ⚠️ **折线是仓里没有的东西**：全仓 `grep` `polyline|<svg|createElementNS` **零命中**（现有全是柱/网格/热力图）
  ⇒ 新组件。守：① 色值只从 `A_constants.js` 取；② **出数据的纯函数与渲染分开**（纯函数进 `npm test`）。
- ⚠️ `goal.mode === 'count'` 时两张图的 y 换成**题数**（同一个形状，同一份口径：只是"每题记 1 分"）。

### 13.2 落地的形状

**① 一条主线 + 一个旋钮（范围）、一个筛子（条件）**（用户 2026-10-14 定稿）：

```
题集 = 副页里的题                ← 边界：计划绑的那个副页（含 C/W/S 子树展开；同一题只算一次）
     ∩ 范围根子树                ← 范围根**留空 = 超级根**（`state.rootId`，子树 = 全部题）
     ∩ 条件（plan.pick 四维）     ← **永远**生效（不再有"哪种来源吃条件"的分叉）
```

- ★ **"副页范围应该是默认的"**（用户在问"是不是有可能选中副页外的题"之后补的）⇒ 步骤①就是边界，
  后面全在池子里筛，**题集永远是副页的子集**。
  ⚠️ 范围根落在副页外 ⇒ 一道题也挑不出来（`rootsInPage === 0`，界面提示"这些范围根不在这个副页里"）。
  要"自动跟着数据变"就**在副页里放整场/整个系列**（它的子树长大 ⇒ 新题自己进来）。
- ★ **不再有"两条来源"**（用户："**「就用这个副页里的题」就是无选中时自动选超级根节点的逻辑**"）：
  范围根**留空** ⇒ 自动取超级根（`state.rootId`）⇒ ∩ 池子 = 池子本身 ⇒ 于是"就用这个副页里的题"
  **不是另一种来源，而是同一个旋钮的默认值**。因此界面上**没有「题集来源」下拉**，
  只有「范围根：整个副页（超级根）／你取下来的那几棵」+ 条件。
  ⚠️ 落地上"留空"时**不真去走一遍超级根的子树**（那等于整棵树，白走）—— 不过滤即等价。
  ⚠️ `plan.source` 保留为**兼容字段**（旧包/旧存档原地往返），值由 `rootIds` **推出**
  （`ops/plan.js:normalizePlanShape`），**读的地方一律不看它**（`planSourceOf` 也是推的）。
- ⚠️ **"CCPC 2023"不用新增"年份维"**：树上 `W/S/C` 那三层**本身就是范围体系** —— 选那个 `S` 当范围根即可。
- ⚠️ **条件里不放 `statuses`**：`matchesProblemFilter.statuses` 是"挑题时的状态筛选"，
  而计划的"做完"由 `plan.statuses` 定义 —— 两个 statuses 是**两件事**，别混（`pick` 只留四维）。
- ★★ **范围只有"存下来的快照"这一种**（`plan.rootIds`），**没有"实时跟随标记"那一层** ——
  用户 2026-10-14："**怎么还有实时和快照两个版本的…能不能稳定一点**"。
  `v9.4.5`~`v9.4.8` 曾经在这里挂过一条"按副页里的标记**实时**筛"的判定
  （`planEligibleOf` + 复用 `view/eligible.js`），它与「取当前选中」做的是**同一件事的两种版本**：
  两个旋钮互相打架，而且那颗 ○ 是**全局临时**的（主树/副页共用，统计页那几个筛选模式也读它）
  ⇒ 为别的事点两下 ○，计划的题集就跟着变。**整层删掉**：
  `planProblemsOf` 不再收 `opts.eligible`，`plan.filterMode` / `PLAN_FILTER_OPTIONS` / `planEligibleOf`
  全部不存在。想改范围就再取一次快照。
  ⚠️ 页签那颗 ○（`page.selected` = 整页映射覆盖）**不算标记** —— 它归**统计页**那一套筛选模式管。
- ★ **「取当前选中」= 把当前标记存成快照**：按一下把**被标记的那几点**收成 `rootIds`
  —— 主树节点的勾 **+ 当前副页里被勾的虚拟节点**（`refId` 回真实节点）；
  **范围根 = 标记点里"父没标记"的那些**（每个根取整棵子树；父子都标记只留父 —— 题集一样、且省一趟遍历），
  界面要写明"你标记了几个、哪几个被合并了"。
  ★ **"我要这些节点"一律由选择系统表达**（用户 2026-10-14："范围根的多选器，功能**全部由选择系统负责**
