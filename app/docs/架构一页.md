# Acm_Tree 框架说明（一页；要能一口气说完）

**一句话**：把散在十几个爬虫里的「比赛 / 题目 / 提交 / 榜单」原料，按**唯一真源**的规则规范化、合并、判定，
产出一个**带着依据、可回代、可复现**的包；应用只负责读它、改它、再把它导回去。

## 一、五层 + 两条通道

| 层 | 干什么 | 落地 |
|---|---|---|
| **L0 原料** | 抓下来的东西**原样**留着（归档 + 缓存），不许在抓的时候顺手加工 | `acm-data/raw/Scaper/`（每个来源一个适配器） |
| **L1 规范** | 原料 → 统一形状的**片段**（crate）：键、字段、来源、依据在这一步定死 | `xcpc_pipeline.py` + `05 xcpc/*_adapter.py` |
| **L2 合并** | 片段 → 一棵树（同一场、同一题只能有一处） | `crate-merge.mjs` |
| **L3 判定** | 分类 / nature / 合成归属 / 难度 / 冲突 | `synth-bind.mjs`（建组 + 按 nature 绑定）、`field-coverage.py`；口径住在 `src/core/` |
| **L4 发布** | `all_nodes.json` + 随包报告（体检 / 需求 / 回代核对） | `scripts/build-all.py`（**14 步**链：注册表→**QOJ 提交抓取**→**杭电/牛客两棵树**→产包→合成归属→题目绑定→补一遍回代→落位→CLIST→试跑→体检→需求→随包报告；离线档 13 步 —— 抓取那一步必然联网，整步不进表） |

- **人 → 脚本**：人只做两件事 —— 往节点里**填**机器判不出的值（留 `manual:set` + 依据 id），或**回代**。
- **脚本 → 应用**：应用只**读** L4 的包；它的改动要人点了才回灌。**脚本不读应用状态，应用不改原料。**

## 二、单一真源（bug 的根都在这条）

「加一个东西要改 N 处」的设计一律算失败。判据只能住在**一处**，其余全部**派生**：

- 顶层用户字段：`A_registry.js` 的那**一张表** ⇒ 落盘 / 导出 / 快照 / 导入全从它来（新字段不登记就红）。
- 字段应有与配色：`fieldRegistry.js`（`EXPECT_*`）；结构键：`fieldmap.RESERVED_KEYS`（`parse` 直接 import）。
- 跨语言那一份（Python 也要读同一张表）：**手抄 + 对拍** —— JS 测试解析 `.py` 逐项比，不指望人记得同步。
  ⚠️ **那张清单就在判据里**：`src/test/crossLangTables.test.js`（判题结果词表 / "应有"谓词的键 /
  分类树的三片特殊叶子…）—— 要加一对新的，**加在那一个文件里**，别在文档里再抄一份名单。
- 离线这件事：`Scaper/lib/read_modes.py` 一处口径（`--cache-mode / --retry-mode / --force / --offline`）。
- 忘掉就红：`npm test`（其中一条把**每一套 Python selftest** 真跑一遍：`src/test/pythonSelftests.test.js`
  的清单就是"规矩"）· `npm run test:smoke` · 语法扫 `.py`（`python -B scripts/syntax-sweep.py` 自报）。
  ⚠️ **别在这儿抄文件数/项数**（会漂）：跑一次自己看 —— `npm test` 与 `npm run test:smoke` 结尾各报一行总数，
  各 selftest 自己也报项数。

## 三、不变量（都能机器验证）

1. **幂等**：同输入两次构建一致 —— ⚠️ 比的是**记录**，不是整文件字节（`generatedAt` 每次都不同）。
2. **守恒**：导入 → 导出 → 导入，字段一个不丢。
3. **全序**：冲突结果唯一、与遍历顺序无关（组头年份 = 依据级别最高、同级取最早）。
4. **可解释**：任何非空值都答得出「凭什么」（规则 id）与「谁写的」（来源 / `manual:set`）。
5. **离线绝不联网**：`--offline` 时 socket 层装着闸门 —— 任何出站连接当场报错并**点名调用点**。

## 四、人机分工

机器管**能算的**与**能拿的**；拿不到 / 算不出的按四档记账：真缺 · 可疑 · 有证据"实际没有" · **多半拿不到** ——
**后两档不算缺**。要人动手的**只有真长出条目时**才有 —— 那些条目**在应用里实时算**（判重整理页
**⑤ 冲突栏**：**年份警报 / 算不出键 / 该换键**这三样才算"要人动的"；低可信年份差异、同组分类/地区不一致、
注册表排除、疑似被拆开的组都**只记账**），**不另存一份清单**（存了就会跟树状态
脱钩成第二套口径）：出现条目才需要人补值 → 回代，一步到位。
⚠️ 人填过的东西**不会再丢**：`src/test/natureAssignments.test.js` 有一条数据驱动守卫，逐格核对
"`nature-assignments.json` 里每一条手填都在包里对上"（手填是最不可再生的 —— 脚本算得出年份，
算不出"东北四省"这种人为划定的地区）。

## 五、"绿"为什么不算数

- 每条修复都配一条**回归就红**的守卫，且**破坏性验证**过（把修复改回去，必须看到红）。
- **守卫自己也要证明它会咬**（"守卫出 bug 你怎么判？"）：源码级 lint 最容易写成恒真，已逮到 10+ 条。
  办法不是再写一条守卫（无穷递归），而是——**扫描抽成纯函数，在同一个测试里喂"已知坏样本必命中 / 已知好样本必放行"**；
  能看**语法树**就不看正则（换引号、拆行、改变量名都躲不掉）。
- 不依赖自己判据的锚：**记录级 diff**（可复现）、**socket 层实测**（离线）、外部源抽样。
- 反例（已写进 §2.6）：0 断言也 exit 0、源码窗口搜词、自证断言、没人跑的 selftest、
  **没人 import 的文件里的 SyntaxError** —— 这些"绿"一律当红处理。

## 六、一句话收尾

**原料只进不改；判据只有一处；人的决定能回代；产物可逐条复现；离线的门装在最底下。**
